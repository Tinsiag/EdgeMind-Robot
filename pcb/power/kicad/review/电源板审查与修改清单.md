# 电源板 KiCad 审查与封装同步记录

审查日期：2026-10-02。工程：`ProPrj_power_2026-10-02`，检查工具：KiCad CLI / Python API 10.0.5。

本次以用户最新确认的 **双路 AT8236 模块**为准。文档中的 DRV8874 是旧选型建议，不作为本板必须采用的器件。用户后续提供的资料图显示 MD-AT8236 V1.0 类接口，已确认模块标称参数、VCC 输入方向及 A/B 线序；模块原理图、孔中心距和实测电流仍缺。最新核对见 [AT8236 模块资料核对](../../../../doc/电机/AT8236模块资料核对.md)。

## 结论

现有图可以作为“两路独立 5V 降压＋双 AT8236 模块转接＋双编码电机接口”的设计基础，但**尚不能满足完整机器人电源板需求，也未达到投板条件**。

原理图已有清楚的功能分区，两路 Buck 的基本连接与 MP2236 引脚定义相符。两路都已画成 5V，预算中关于“旧 9V ACG720 支路”的描述不符合本次检查的这套工程。主要不足是 USB-C 源端保护、电池输入保护、动力急停与监测、3.3V 来源及 AT8236 模块的接口定义没有落实。图纸可读性也需要改善：`VCCOUT/VCCOUT1` 未标明分别给哪块计算板，接口只使用通用排针符号，缺少模块引脚功能和版本说明，导入产生了大量极短悬空线段。

本次完成了导入修复、封装绑定与原理图/PCB 对应。电源架构、保护器件及实际布线修改列为下一次电路改版工作，没有将未验证的模块或器件参数写成已确认的设计。

## 必须修改的电路和物料

### 1. 补齐电池保护和动力安全链

- CN1 到 VCCIN 之间没有主保险、防反接和明确的总开关/保护链。外接驱动模块即使自带防反接，也不能保护本板两路 Buck。
- SW2 `SS-12D10L5` 串在全部 VM 动力供电路径中。必须按两电机启动/限流电流及后续执行器负载核实其直流开断能力，优先用急停触点控制合适的直流接触器或大电流高边开关。
- 增加急停状态反馈、硬件禁止信号与默认下拉。急停解除、驱动过温恢复、通信恢复后，系统仍须保持未解锁，避免自动恢复运动。
- 增加电池单节保护/监测方案及低电量告警。现有 Buck EN 的 300kΩ/130kΩ 分压启停点约在 4V 附近，远低于 3S 正常保护区间，不能当作电池欠压保护。Linux 应留有受控关机时间。
- VM 侧没有本板的大容量储能电容。需核实模块已有电容，并在模块附近保留合适耐压的低 ESR 母线电容、旁路及回生吸收措施。

### 2. 补 USB-C 源端控制与每口保护

USB1/USB2 的 VBUS 目前直接连到各自 Buck 输出。R4/R5、R8/R9 的 10kΩ 上拉只表达 CC 电流宣告意图，没有检测接入设备后才打开 VBUS 的功能。应每口增加固定 5V 源端控制、限流/短路、放电和所需的反灌/过压保护。TPS25810 是文档中可继续评估的方案；反向阻断等功能必须逐项按所选器件确认，不能默认全部内置。[TI TPS25810 数据手册](https://www.ti.com/lit/ds/symlink/tps25810.pdf)

VBUS 和 GND 的两组并联触点在原理图中已正确接到同一网络。仍需核对当前插座 `LAIL-TYPE-C-16PIN-08-WT` 的真实 3A 额定、焊盘、开槽及外壳接地。ACG720 的 Type-C 是否给整板供电、允许电流、供电选择和与调试 USB 的隔离仍是前置条件。

### 3. 确认 AT8236 模块的通道和控制边界

这是外接模块方案，本次绑定的是模块插接排针，**没有在本板上添加 AT8236 裸芯片封装**。

- J5/J6 是一组模块排针，J7/J8 是另一组。资料确认 J5/J7 的输出是 AOUT，J6/J8 的 1、2 脚应分别对应 BOUT2/BOUT1，当前 NC。每块使用 A 通道、未用 B 输出不连接的方案成立。
- J5 同时出现 `LAOUT1/2` 和 `LBIN1/2`，J6 则出现 `LAIN1/2`；右侧同理。资料确认这种 A/B 跨两排分布是模块原有布局，原理图逻辑网络相符。**但 PCB 两排都按相同 X 方向排列 1→7；模块要求对排反向。J6/J8 需绕排针中心旋转 180°并重布线，或改为编号正确的整体模块封装。当前不能直接插模块上电。**
- 普通 AT8236 的 IN1/IN2 与 `LF_ENA/LF_ENB` 等编码器信号是不同用途，不要把编码器 ENA/ENB 当驱动使能。当前没有独立的全局使能/急停输入和驱动故障反馈。
- 资料给出模块 VM 5–17V、IN 0–5.25V、VCC 参考输入 0–4V、PWM 上限 100kHz、每路 3A 标称/6A 峰值。3.3V IN 高低电平与芯片条件相容。VCC 不得接 5V，也不能当成编码器电源输出；实际 VREF/ISEN 限流取决于模块实现。6A 在芯片手册绝对极限表中出现，不能作为持续堵转能力。[杭州中科微 AT8236 手册 V1.1（原厂资料镜像）](https://atta.szlcsc.com/upload/public/pdf/source/20210923/1552D95CBAF8BE780D06AE79E7783380.pdf)
- 当前 FPGA 文档仍采用 TB6612 的独立 PWM/STBY 接口，需适配为 AT8236 两个 IN 的 PWM 控制；不能只连接原有方向输出而丢弃 PWM。资料图真值表 00=滑行/休眠、10=正向、01=反向、11=制动。
- MG513 的 3.2A 堵转值来自项目中的电机资料，不能直接当作模块持续电流要求或设定值。实测启动、限流和温升后确定模块能力。
- 若两台两相步进电机都使用 AT8236 实现，需要每台两路 H 桥以及合适的恒流控制；与两台直流电机合计需要六路桥。现有两块双路模块合计四路，数量和接口均不足。

### 4. 明确 3.3V 的来源

当前 /3.3V 同时连接两组模块排针、控制板接口与编码器端子。资料已明确 VCC 为外部参考输入，**不能由该模块给此网络供电**。必须定义由本板稳压器还是经过能力核实的 FPGA 电源提供；本图仍缺板上 3.3V 稳压源。VCC 的内部参考连接和限流阻值需继续核实，固定 3.3V 并不自动对应 3A 限流。

按已确认来源补独立稳压/隔离和传感器分配接口，预算至少覆盖两编码器、IMU 及实际数量的 ToF。接电机前确认霍尔/GMR 版本、六针线序和编码器供电/输出电平。

### 6. 保留两路 Buck 的基础，复核瞬态保护与热设计

两路 `82kΩ/11.1kΩ` 反馈分压按 0.6V 典型基准计算：`0.6 × (1 + 82 / 11.1) ≈ 5.03V`。这是设定值估算，不是板端带载结果。MP2236 的正常输入上限为 18V，绝对最大值为 20V；电池正常电压可覆盖，但电机回生尖峰需要单独处理。[MPS MP2236 数据手册](https://www.monolithicpower.com/en/documentview/productdocument/index/version/2/document_type/Datasheet/lang/en/sku/MP2236/document_id/4411/)

D1 是安邦 `SMF12A`，接在 VM 而非 Buck 直接取电的 VCCIN。需取得此具体器件手册核实其反向工作电压与动态钳位。作为同型号的参数示例，Littelfuse SMF12A 的反向工作电压为 12V、指定脉冲钳位为 19.9V；前者低于满电 12.6V，后者已靠近 MP2236 绝对最大值，且线路寄生还会增加尖峰。**不能把旧建议中的 SMBJ15A 不加核算地替换进来**，应共同选择 TVS、吸收/过压关断及 Buck 耐压。[Littelfuse SMF 系列手册](https://www.littelfuse.com/~/media/electronics/datasheets/tvs_diodes/littelfuse_tvs_diode_smf_datasheet.pdf.pdf)

器件额定电流不保证现有两层板的输出能力。需按每口实际 3A、动力启动电流、铜厚、过孔及连接器能力核算温升，并测试两口带载、电机换向、低电量和插拔时的电压。

## 本次已经完成的修改

1. 53 个物理元件全部通过原理图 UUID 与 PCB `path` 关联；逐项核对 189 个引脚/焊盘编号与网络。
2. 将原 PCB 的 `$1N...` 和不带层级路径的标签网络，通过相同位号/焊盘的连接对应到 KiCad 原理图网络；共核对 39 个原有非空网络映射。原理图电气连通关系保持一致。
3. 新增项目本地 `ProPrj_pow-easyedapro.pretty` 与 `fp-lib-table`，共 23 个封装文件。包含 14 类基础封装及 9 个保留原导入图形细节的实例变体；没有因统一库文件而移动焊盘。当前已无封装库缺失和封装副本不匹配告警。
4. C6/C7/C11/C14/C15/C16 从原理图的 0805 绑定改为 PCB 已有的 0603，且它们的 Supplier Footprint 原本也标为 0603。其容值/采购确认仍见上表。
5. 118 个 `thru_hole + 0.001mm 钻孔` 假通孔改为真实 SMD，层改为 `F.Cu/F.Paste/F.Mask`。USB 外壳真实槽孔及排针通孔保留。原先五处由假通孔触碰底层走线造成的短路告警已消除。
6. 四个无位号 3mm 固定孔设为 H1–H4、NPTH，并排除 BOM/贴装。图框排除板上器件与 BOM；35 个电源符号补齐位号。
7. 修复电阻、电容、连接器等被导入为 Input/Unspecified 的电气类型，并按 MP2236 手册配置电源和控制引脚类型。修复电源符号缓存/本地库对应，补 PCB 数值及元件属性，LED 补通用 Value。
8. 使用 KiCad 原生功能重填九个实际铜皮区。原导入另含 97 个自动泪滴缓存区，原生重填时被清理；重新布线时应按焊盘和过孔设置生成泪滴。原始缓存仍在备份中。

元件位置、焊盘位置/尺寸及既有 337 段走线、23 个过孔的几何均通过修改前后对比。PCB 依然是原来的两层 100×50mm 布局。本次封装绑定成功只证明项目库、编号和网络一致，不代表特定模块的机械尺寸已经验证。

## 检查结果与 PCB 待修改项

| 检查 | 修改前 | 修改后 |
| --- | ---: | ---: |
| ERC | 230：22 错误＋208 警告 | 36：4 错误＋32 警告 |
| DRC 一般违规 | 543：479 错误＋64 警告 | 89：77 错误＋12 警告 |
| PCB 未连接项目，另计 | 0 | 9 |
| 原理图/PCB 一致性问题，另计 | 224 | **0** |

修改前“0 未连接”受假通孔及导入铜皮缓存影响，不能作为电源走线正确的证明。修正焊盘后出现的 9 项才是当前检查需要处理的断连；同一区域的错误可能有多个描述，不代表九条独立物理断线。

剩余 ERC：四条电源输入未被电源输出驱动，需按真实电源来源补正确标志；32 条极短线段的悬空端点警告，需整理图形。**不要通过随意添加 PWR_FLAG 把缺少的实际电源掩盖掉。**

剩余 DRC：48 间距、17 热焊盘连接不足、9 铜到板边间距、3 courtyard 重叠、8 丝印到板边、4 丝印压铜。没有降低项目规则，也没有新增规则排除来消除这些结果；报告沿用工程已有规则及已有 ignored_checks。

优先处理的 PCB 区域：

- **U1/U5 GND**：输出功率地存在真实断连，先连接正确地回流，不能仅靠模拟通孔或孤岛铜皮。
- **U1 VIN、C9 与输入铜皮**：重新接通输入回路，检查热焊盘连接和狭窄铜颈。
- **L1→C4/C5、L2→C12/C13**：两个输出网络存在铜皮岛及断连，重新布通各自输出路径。
- **D1/R15/LED1/SW2**：封装 courtyard 重叠，需重新布局并核实实物装配空间。
- **USB1/USB2**：封装内有 Edge.Cuts 开槽图形，导致多条铜到板边不足。按所用插座尺寸图复核槽口，不能未经依据删除开槽或把违规一律忽略。
- **CN1**：4 号焊盘到外边缘约 0.397mm，小于当前 0.5mm 约束；调整入口位置或明确制造能力后合理设定规则。
- **大电流路径**：现有线宽以 0.254/0.508/0.762mm 为主，必须逐网核查 VCCIN、VM、两路 5V 与电机输出；不能据此直接宣称达到预算里的 20A 短时目标。

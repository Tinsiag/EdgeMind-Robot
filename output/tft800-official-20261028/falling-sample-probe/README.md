# 从滚动色块版继续：只反转PCLK

SHA256：`7c0e06d8a814430e7b22d2a09787f55ccca7f3c1686df8786b0c4c4afa29e198`，位流`impl/pnr/probe.fs`。

用户在官方原版及完全断电重启均白屏后要求“你把我们刚刚能显示滑块的那个拿来再改改”。本版直接以14ebf7bd控制线对照为基础，RTL唯一差异是clock_pad的输入从pclk改为~pclk；官方800×480/33MHz扫描、原两列四行色块、RGB输出寄存、三阶段DE/背光对照、引脚及时序约束均保持。版本UserCode改为0xA72E。

这次只验证下降沿采样假设，数据在外部PCLK上升沿附近更新，下降沿处于稳定区间。不是已确认面板型号的采样边沿选择，也不宣称对上升沿采样面板满足建立保持。

阶段与滚动版相同：D6/D7均灭=AB22输出DE、AB21高；仅D6亮=AB22高、AB21输出DE；仅D7亮=两脚都输出DE。每阶段8.064秒。正确图案应两列四行黑/蓝、红/紫、绿/青、黄/白。四电机OBUF直接GND，不ARM。

完整仿真覆盖三阶段循环和每阶段完整图案；仅阶段帧数缩为3，PLL理想33MHz、真实IOBUF模型。PNR布局1/布线1、时序驱动/hold修复，无编译WARN/ERROR，setup+2.835、hold+0.247、recovery+29.230、removal+0.353、MPW+7.395ns。

本次Gowin将PCLK反相实现为LUT1，并在数据输出时钟路径生成零延迟split INV，却未在SDF中给出该段时钟互连。审查未按0替代实际路由：对每个输出用同次STA的该端点tNET上界（另加0.002ns覆盖报告舍入）和非负下界约束缺失时钟段，再与SDF中PCLK和数据CQ/IO路径按跨角点最保守值比较。下降沿最小setup界13.2745、hold界12.1405ns；减8ns接收检查预算、1ns未实测板线偏斜、0.3ns时钟预留后余量2.8405ns。详见REVIEW.json；不是全路径SDF实测或板端测量。

烧录脚本已增加等待wakeup/DONE及UserCode比对。原先即时状态0x30000460并不表示配置已完成，不能把命令返回0当作运行验收；此次会保留只读状态轮询，失败不重擦写。官方原版冷启动后已读到0x70026020、UserCode0xFBC9，说明该版配置完成且版本正确，但用户实物仍白屏。

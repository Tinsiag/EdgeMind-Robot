2 Overview 
Gowin DDR3 Memory Interface IP is a commonly used DDR3 
memory interface IP that complies with the JESD79-3F standard protocol. 
The IP design includes DDR3 memory controller (MC) and the 
corresponding physical interface (PHY). Gowin DDR3 Memory Interface IP 
provides you with a general command interface which can connect with 
the memory chip to access and save data.

3.2 Operating Frequency and Bandwidth Efficiency 
The data rate of the DDR3 SDRAM that Gowin DDR3 Memory 
Interface supports is as follows:  
 In 1:2 clock ratio mode, the maximum rate is 533 Mbps. 
 In 1:4 clock ratio mode: 
- For GW5A(R)(S)-25 devices, the maximum rate is 1100Mbps. 
- For GW5A(T)-60 devices, the maximum rate is 1100Mbps. 
- For other devices, the maximum rate is 800Mbps. 
The bandwidth efficiency of Gowin DDR3 Memory Interface IP is as 
follows: 
 In 1:2 clock ratio mode with a burst length of 4, the bandwidth 
efficiency is 50%. 
 In 1:2 clock ratio mode with a burst length of 8, the bandwidth 
efficiency is 90%. 
 In 1:4 clock ratio mode, the bandwidth efficiency is 90%. 
Gowin DDR3 Memory Interface IP employs the Verilog language, and 
it is applied to GW2A and GW5A (excluding 15K) series chips. Due to 
differences in device density and speed, resource utilization may vary.

4.2 Memory Controller  
Memory Controller is located at MC layer, realizing protocol layer 
functions. Internal state machine is for BANK, ROW, COL, and refresh 
control. Memory Controller receives user-side read and write commands, 
stores the commands in FIFO logic internally, converts read and write 
commands into detectable interface timings on PHY side, and inputs to 
PHY side.

4.3 PHY 
The PHY provides the physical definition and interface between MC 
and external DDR3 SDRAM, receives commands from the memory 
controller on MC layer, and provides the DDR3 SDRAM chip with interface 
timing. 
The structure of PHY includes four modules: initialization module, 
data path, command address control path, and I/O logic module, as shown 
in Figure 4-2.

4.3.1 Initialization Unit 
The initialization module is mainly used for initialization and read 
calibration after DDR3 SDRAM power-on. After initialization and read 
calibration are finished, the "init_calib_complete" signal will be high from 
low, indicating that the initialization has been completed. 
Note! 
Read/write operations are not allowed to be performed until the init_calib_complete  signal 
is pulled up. 
Power-on Initialization 
According to the JESD79-3F protocol, there is a need to initialize the 
DDR3 SDRAM (chip or DIMM) after power-on. This includes the reset, 
clock enable, mode register configuration, and ZQ calibration. 
4.3.2 Data Path Unit 
Data path includes write data path and read data path. 
4.3.3 Control Path Unit 
The command/address control path is a single path that receives the 
command and address signal sent by the Memory Controller and 
cooperates with the data path to process the write and read data delay

4.4.2 Clock 
The IP has three clocks, two input clocks, clk and memory_clk, and 
one output clock, clk_out. 
As shown in Figure 4-4, clk is used to generate some synchronization 
and control signals which act on the main logic of the IP (PHY layer and 
Memory controller). clk is required to be a low-speed continuous clock with 
a recommended value of 50MHz, and the input of the on-board crystal can 
be connected to clk.

4.4.3 Reset  
The IP includes the input signals rst_n and pll_lock, as well as the 
output signal ddr_rst. As shown in Figure 4-5, rst_n is required to do a 
synchronization release under the clk before sending it to the IP. rst_n will 
reset the Sync_mod module logic, and then Sync_mod waits for pll_lock. 
After pll_lock is locked, Sync_mod will output ddr_rst as the global reset of 
the IP and send it to the user. Any reset logic can be connected to rst_n, 
and pll_lock can only be connected to the LOCK signal of the PLL. If 
pll_lock is not connected to the LOCK signal of the PLL, the IP will not be 
able to detect whether the clock is stable, and DDR initialization failure is 
prone to occur.

4.4.8 Read Data 
You can read the data from the DDR3 SDRAM using the user 
interfaces, including rd_data, rd_data_valid, and rd_data_end.

4.4.9 Refresh 
Refresh 
The DDR3 SDRAM array needs to continually refresh to ensure the 
data is not lost. Therefore, Gowin DDR3 Memory Interface IP is required to 
send the refresh instruction to DDR3 SDRAM periodically. Gowin DDR3 
Memory Interface IP requires ad interval of tREFI time to generate refresh 
command; after the refresh command is generated, MC will precharge all 
banks after executing the last read/write command, and then execute 
Refresh command. The refresh operation has higher priority. 
Self-Refresh 
You can send a self-refresh request through the sr_req port and 
configure DDR3 SDRAM with self-refresh mode. In the self-refresh mode, 
DDR3 SDRAM will automatically refresh the memory array without a 
refresh instruction from Gowin DDR3 Memory Interface IP. 
Gowin DDR3 Memory Interface IP will return the sr_ack signal to 
users after the self-refresh configuration of DDR3 SDRAM is completed, 
indicating that the DDR3 SDRAM is configured with self-refresh mode.

4.5 AXI4 Interface 
The memory controller supports the industry-standard AXI4 interface. 
The AXI4 slave interface module maps AXI4 transaction information to the 
internal memory control logic. The AXI4 slave interface is optional. Users 
can enable or disable generation of the AXI4 slave interface through the 
"AXI4 Interface" option in the IP configuration GUI. For detailed protocol 
information on the AXI4 interface, refer to the Arm AMBA AXI 
Specifications. 
All AXI4 interface parameters can be configured through the "AXI 
Interface Options" in the IP GUI. 
4.5.1 Arbitration Mode 
The AXI4 write and read channels support five arbitration modes, 
which are described as follows: 
 Mode 0: Read and write channels have equal priority. The arbiter 


PDF PAGE 26
4 Functional Description  
  
IPUG281-2.6E 19(35) 
 
alternates between the read and write channels on every clock cycle. 
 Mode 1: Read and write channels have equal priority. When both 
channels are idle, the arbiter continuously selects the write channel. If 
read and write requests occur simultaneously, the write request is 
serviced first. If the last transaction issued by the master was a write, 
the arbiter gives priority to the read channel in the next arbitration; if 
the last transaction was a read, the arbiter gives priority to the write 
channel. 
 Mode 2: Read-priority mode. When read and write requests occur 
simultaneously, the read request is serviced first. 
 Mode 3: Write-priority mode. When read and write requests occur 
simultaneously, the write request is serviced first. 
 Mode 4: Read and write channels have equal priority. The arbiter 
switches to the write channel when either of the following conditions is 
met: 
- Only write requests are present and no read requests exist. 
- Both read and write requests are present, but the read channel is 
blocked and cannot continue. If the blocking duration reaches 256 
system clock cycles, the arbiter switches to the write channel. 
Note! 
The conditions for switching to the read channel are symmetrical to those for switching to 
the write channel. 
 Mode 5: Read-priority mode. When both read and write requests are 
present, the arbiter prioritizes the read channel. The write channel 
starts a wait timer, and if the wait time reaches 256 system clock 
cycles, the arbiter forcibly switches to the write channel.

5ODT 
On-Die Termination (ODT) is an important function of DDR3 that can 
help reduce signal reflections on DQS, DQ, and DM lines, thereby 
improving signal quality. Both the FPGA and DDR3 chips support ODT 
function. When the FPGA sends DQS, DQ, and DM signals to the DDR3 
chip, the IP activates ODT on the DDR3 side by driving the ODT pin high, 
while the ODT on the FPGA side is automatically disabled. Conversely, 
when the DDR3 chip sends DQS and DQ signals to the FPGA, the IP the 
IP deactivates ODT on the DDR3 side by driving the ODT pin low, and the 
ODT on the FPGA side is automatically enabled. 
It is not always necessary to enable ODT on the FPGA side, as 
enabling it increases power consumption. In practical applications, users 
can try operating without enabling ODT on the FPGA side. If DDR3 
initialization fails or data errors occur, ODT on the FPGA side can then be 
enabled for debugging. 
In Gowin Software, ODT is disabled by default. Users can enable it 
via the FloorPlanner tool. Taking GW5A series of FPGA as an example, 
the method for enabling ODT is described below. As shown in Figure 5-1, 
set the Single Resistor of DQS and DQ to 50. If the setting of 50 does not 
yield good results, users can try other values. Gowin Software enables the 
Diff Register of DQS by default, and users need to disable it.

7.1 Gowin DDR3 Memory Interface IP Parameters 
Gowin DDR3 Memory Interface IP supports DDR3 SDRAM devices. 
Users shall configure the static parameters and timing parameters of the 
Gowin DDR3 Memory Interface IP according to the design requirements. 
The static parameters are described as follows. 
 User Interface: The user interface allows you to select either Controller 
or PHY . When Controller is selected, the IP includes both Controller 
and PHY functions. When "PHY" is selected, the IP only includes the 
PHY function, and the user is required to implement the controller 
function independently. 
 Memory Type: Supports configuration of four memory types: 
Components, RDIMMs, UDIMMs, and SODIMMs. 
 Memory Clock: Used to set the high-speed clock frequency for the IP. 
The configured frequency should match the clock frequency 
corresponding to the DDR3 interface rate. For example, if the DDR3 
rate reaches to 800 Mbps, this option should be set to 400 MHz. 
 CLK Ratio: Used to define the ratio between the Controller and the 
PHY . Options are 1:4 or 1:2. The rate of the PHY is the same as the 
rate of the Memory Clock, while the rate of the Controller is 1/4 or 1/2 
of the Memory Clock rate. 
 Dq Width: The total DQ width. For instance, if a single DDR3 chip has 
a DQ width of 16 bits and the IP drives two such chips, then the Dq 
Width should be 32 bits. 
 Dram Width: The DQ width of a single DDR3 chip. 
 Rank Address: Fixed to 1. The IP does not support the rank address, 
so this value does not take effect. 
 Bank Address: Fixed to 3. 
 Row Address: Row address width. The user should refer to the 
datasheet of the selected DDR3 chip to configure this value. 
 Column Address: Column address width. The user should refer to the 
datasheet of the selected DDR3 chip to configure this value.

 SIM: Should be enabled during simulation to shorten DDR3 
initialization time; disabled in non-simulation environments. 
 Address Width: Read-Only; user interface address bus width, 
calculated as Rank Address + Bank Address + Row Address + Column 
Address. The most significant bit (Rank Address) is unused and must 
be fixed to 0. 
 Data Width: Read-Only; user interface data bus width; When CLK 
Ratio is set to 1:4, the width equals Dq Width* 8; when it is set to 1:2, 
the width equals Dq Width*4. 
 Mask Width: Read-Only; user interface data mask bus width; when 
CLK Ratio is set to 1:4, the width equals Dq Width*8/8; when it is set 
to 1:2, the width equals Dq Width*4/8. 
 Burst Mode: Used to configure the burst mode of the DDR3 chip. 
Supports BC4 and BL8. 
 Burst Type: Used to configure the burst type of the DDR3 chip. 
Supports Sequential and Interleaved. For detailed descriptions of 
Sequential and Interleaved, please refer to the JESD79-3F 
specification. 
 CAS Latency (CL): The delay from a read command to the first valid 
data. The total read latency (RL) is calculated as: Additive Latency 
(AL) + CAS Latency (CL). 
 CW Latency (CWL): The delay from a write command to the first valid 
data. The total write latency (WL) is calculated as: Additive Latency 
(AL) + CW Latency (CWL). 
 Additive Latency (AL): Supports configuration of 0, CL−1, and CL−2. 
DDR3 supports the Posted CAS, which can improve efficiency when 
there is a timing conflict between Active and Read/Write commands. 
 Write Recovery: Refers to the number of clock cycles that must be 
waited after completing a valid write operation in an activated bank 
before issuing a precharge command. 
 Rtt Nom, Rtt Wr: DDR3 On-Die Termination (ODT) settings. Rtt_Nom 
supports OFF, 20Ω, 30Ω, 40Ω, 60Ω, and 120Ω. Rtt_Wr supports OFF,

7.2 AXI4 Interface Parameters 
Data Width 
Data Width refers to the bit widths of the AXI4 write data bus and read 
data bus, read-only. When the CLK Ratio is set to 1:4, the data width 
equals Dq Width × 8; when the CLK Ratio is set to 1:2, the data width 
equals Dq Width × 4. When ECC is enabled, Dq Width is fixed at 64. 
When ECC is disabled, Dq Width equals the actual total DQ width. 
Address Width 
Address width refers to the bit width of the read and write address 
buses, read-only. The AXI4 interface uses byte addressing, whereas the 
DDR3 address is not necessarily byte-addressed. For example, when Dq 
Width is set to 8, the DDR3 address corresponds to a byte address, and in 
this case, the AXI4 interface address and the DDR3 address are 
equivalent. When Dq Width is set to 16, one DDR3 address stores two 
bytes of data; the AXI4 interface address and the DDR3 address widths 
are not equal. Therefore, the AXI4 address bus width differs from the 
DDR3 address width. 
ID Width 
ID Width refers to the bit width of all IDs (AWID, BID, ARID, and RID). 
This parameter is configurable, with a valid range from 1 to 16. 
AXI Buffer Type 
Specifies the FPGA resources used for buffers within the AXI4 
interface. Supported options include BSRAM, SSRAM, and REG.

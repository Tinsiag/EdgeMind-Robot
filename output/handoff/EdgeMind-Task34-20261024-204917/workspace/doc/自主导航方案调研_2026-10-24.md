# 自主导航方案调研与现有代码核对

调研日期：2026-10-24，北京时间。本次只阅读现有实现、检索资料并准备独立固化工具，没有编写或部署导航功能，也没有烧录硬件。

## 结论

现阶段最适合复用的成熟方案是 **Linux 主机上的 ROS 2 Jazzy + SLAM Toolbox + AMCL + Nav2，连接现有 A741 FPGA 底层**。先用电脑验证，后续再迁移到板载 Linux 计算机，可以保留绝大多数导航软件与配置。

这里的“可部署”指成熟软件包可以安装和配置，整车仍需一层本项目专用的 UDP/ROS 桥接及标定。没有找到能直接烧进当前 ACG720 / GW5AT-60B、匹配现有传感器和电机接线、完整完成建图定位避障导航的现成位流。检索范围内的 FPGA SLAM 开源项目主要是其他器件的加速器，不能据此承诺存在本板的一键方案。

如果最终要求完全脱离电脑运行，需要板载计算平台，或继续完成现有纯 FPGA 导航工程。电脑运行 Nav2 可以完成自主决策，但有线电脑联调不等于整车已脱离外部计算机。

## 已有纯 FPGA 导航工程的实际状态

`a741-fpga-fusion` 已经写入编码器/IMU 位姿、雷达投影、128×128 栅格、局部匹配、8 邻域 A*、前视跟踪、导航状态机和地图传输，不能把项目描述成“尚无任何导航代码”。但也不能直接启用它作为成熟导航。

- 地图为 50 mm/格，覆盖约 6.4×6.4 m；定位只搜索局部 27 个候选，没有完整全局回环或任意起点重定位。
- 规划逐次扫描 open 集，最坏复杂度较高，规划期间停车；存在完整整车运行时延尚待验证的问题。
- 整车含车轮的外廓、轮轴中心、雷达相对轮轴位置、雷达高度未核实，导航由编译期几何锁禁用。180×254 mm 下壳尺寸不能替代整车轮廓。
- 本机记录的完整编译虽然成功，但融合工程 setup/hold 违例为 **1452/30**，`timing_signed_off=false`。未发布运动位流、未烧录、未实车验收。当前几何锁还可能裁剪部分逻辑，未来解锁后必须重新完整构建。
- 运动主线本机新构建也有 **70/31** 项 setup/hold 违例，不能拿来冒充原稳定发布包。

依据：[融合工程](../code/camera-car-control/a741-fpga-fusion/README.md)、[数据路径](../code/camera-car-control/a741-fpga-fusion/docs/FUSION-ARCHITECTURE.md)、[融合结果](../code/camera-car-control/a741-fpga-fusion/verification/FUSION-RESULTS.json)、[几何锁](../code/camera-car-control/a741-fpga-fusion/config/geometry.json)。这些是保存的构建记录，本次未重新跑综合或时序分析。

## 网上可复用的方案比较

| 方案 | 已提供的能力 | 对当前机器人的适配 | 判断 |
| --- | --- | --- | --- |
| ROS 2 + Nav2 + SLAM Toolbox/AMCL | 二维建图、地图定位、全局规划、局部控制、代价地图、目标点与任务接口 | 增加 UDP/ROS 桥接，配置 TF、整车轮廓、限速与停止条件 | 最优先评估；软件栈可直接安装，整车需要适配 |
| TurtleBot 4 导航参考工程 | 有现成 SLAM/Nav2 启动文件与定位、目标点示例 | Create 3 底盘、树莓派及其驱动与本车不同 | 可参考配置组织和运行流程，不能原样刷镜像后控制本车 |
| LDROBOT 官方 LD06 ROS 2 驱动 | 串口 LD06 转 `sensor_msgs/LaserScan` | 原样面向 `/dev/ttyUSB*`，不能直接消费当前 EML1 UDP 包 | 雷达直连 Linux 串口时可复用；现有接线优先保留并转换 EML1 |
| 现有 CoreSLAM + 自写规划控制 | 已有局部地图与轨迹，Windows 环境现成 | 仍需补定位、规划、跟踪、恢复、动态障碍与验收 | 能做小场地演示，但整体不属于成熟导航的一键部署 |
| 现有纯 FPGA 融合工程 | 算法与上下位机框架已写入 | 须处理几何、时序、大量实测与资源/时延验证 | 可保留为 FPGA 研究路线，当前不可直接部署 |
| acSLAM 等开源 FPGA SLAM | ORB-SLAM2 特征前端等硬件加速参考 | 项目依赖 ZCU104、Vivado/PYNQ 与 CPU 协同，不匹配 GW5AT | 算法/硬件设计资料，不能作为 ACG720 成品导航固件 |

Nav2 官方文档把 SLAM Toolbox 与 AMCL 列为二维建图及定位途径，两者使用标准激光扫描消息；TurtleBot 4 的官方工程也提供先建图、再加载地图定位导航的完整参考流程。[Nav2 建图与定位](https://docs.nav2.org/jazzy/configuration_and_development/first_time_robot_setup_guide/sensors/mapping_localization/)、[TurtleBot 4 启动说明](https://turtlebot.github.io/turtlebot4-user-manual/software/turtlebot4_common.html)。

SLAM Toolbox 上游提供回环、位姿图保存与继续建图能力。保存成图片地图用于 AMCL，与保存位姿图用于继续 SLAM 是不同产物，现有 CoreSLAM 的 JSON 不能直接充当它的位姿图。[SLAM Toolbox 上游](https://github.com/SteveMacenski/slam_toolbox)。

官方 LD06 驱动声明支持 LD06、230400 串口并发布扫描；其旧 README 的 ROS 2 测试说明不能替代本项目在 Jazzy 下的实际编译验证。[LDROBOT 官方驱动](https://github.com/ldrobotSensorTeam/ldlidar_stl_ros2)。

acSLAM 明确采用 ZCU104、Vivado 2019.1、PYNQ Linux，并由专用逻辑与 CPU 协作运行 ORB-SLAM2。这支持“可参考但不直接匹配”的判断，不能把它当作纯 RTL 整车导航。[acSLAM 上游](https://github.com/SLAM-Hardware/acSLAM)。

## 推荐架构与真正需要补的接口

```text
LD06 + 编码器 + IMU
        ↓
现有 FPGA 采集、轮速 PI、PWM、安全锁存
        ⇅ EMC1 / EMS1 / EML1 UDP
项目专用桥接进程，独占 FPGA 控制会话
        ⇅ /scan、/odom、IMU、TF、速度命令
Linux：SLAM Toolbox 建图 → 保存地图 → AMCL 定位 → Nav2 导航
        ↓
速度平滑 / Collision Monitor → 桥接 → 左右轮目标
```

这是拟议分工，不是本次已经部署的系统。首轮可使用 x86-64 Ubuntu 24.04 + ROS 2 Jazzy。Jazzy 在该系统的 amd64/arm64 上有官方 Tier 1 支持，支持期至 2029-05；选它是为了成熟依赖，未声称它是 2026 年最新发行版。[ROS 平台支持 REP-2000](https://raw.githubusercontent.com/ros-infrastructure/rep/master/rep-2000.rst)。

如果使用既有 LicheePi 4A，要先实读所装系统和架构。官方资料显示它采用 TH1520 / RISC-V，不能照抄 ARM64 的 apt 包或镜像；Jazzy 的上述 Tier 1 表不包含 riscv64。据此判断它需要单独评估源码编译、依赖与性能，本次没有核实到可替本车直接部署的 Nav2 整机镜像。[LicheePi 4A 官方介绍](https://wiki.sipeed.com/hardware/en/lichee/th1520/lpi4a/1_intro.html)。

| 桥接/配置项目 | 可复用输入 | 必须完成的处理 |
| --- | --- | --- |
| `/scan` | EML1 原始 LD06 包、CRC、序号、整圈组装 | 米/弧度转换、顺逆时针、扫描时间、缺测表达、外参；不能将 GUI 的旋转设置直接重复叠加到 TF |
| `/odom` | EMS1 同步左右累计计数和 FPGA 毫秒时间 | 计数回绕、轮径/CPR、差速积分、速度与协方差；用连续里程计坐标，不把有回环跳变的地图位姿当作里程计 |
| IMU | 相对航向、角速度、采样时间与有效位 | 坐标符号、角度单位、相对零点及有效性；EMS1 不是完整六轴原始包，不能填造不存在的加速度或绝对姿态 |
| TF | 实测底盘、雷达安装位置 | `map → odom → base_link → laser`，IMU 有自己的安装坐标；每条动态变换指定唯一发布者 |
| 速度命令 | EMC1 原始左右轮命令 `0x11`；轮速 PI 已有 | `vL=v−ωb/2`、`vR=v+ωb/2`，统一限幅和租期；首轮不再额外叠加旧 GUI 的航向外环。Twist/TwistStamped 类型按选定版本显式统一 |
| 导航停车 | 已有 STOP、故障锁存与命令租期 | 导航速度、扫描、里程计任一过期就停车；不能在 Nav2 已停止出新命令后无限重发缓存速度或只续心跳 |
| 控制所有权 | EMC1 会话、电脑控制端口 5001 | GUI 与导航不能各建一个控制会话争抢电机；需要一个所有者仲裁手动/自动/停止 |
| 网络 | FPGA `192.168.0.2`，RTL 固定对端 `192.168.0.3`；遥测 6103、视频 6102 | Linux/虚拟机需能真实使用约定地址和收发路径；默认 WSL/Docker NAT 不能未经验证就当作接通。先关停并发控制 GUI |
| 地图与轮廓 | 现有 PGM/YAML、整车模型 | 核对 origin、尺度、占据阈值、未知区域及方向；整车含车轮外廓和转向扫掠空间必须实测 |

Nav2 的官方 TF 教程规定各坐标系关系；接入的关键是有正确的坐标和时刻，不是把雷达点画出来即可。[TF 官方指南](https://docs.nav2.org/jazzy/configuration_and_development/first_time_robot_setup_guide/transformation/setup_transforms/)。

局部控制可先评估 DWB，或在简单路径场景评估 Regulated Pure Pursuit；后者提供前视追踪、曲率/接近目标限速和碰撞检查，不能把单个跟踪器当成完整动态绕障系统。[RPP 官方说明](https://docs.nav2.org/jazzy/configuration_and_development/configuration_guide/controller_plugins/configuring_regulated_pp/)。

Collision Monitor 可以对激光数据配置停车/减速区域与数据过期停车，适合作为导航输出到桥接之间的一层检查；默认参数必须根据本车延迟和制动实测调整，它也不能替代 FPGA 失联锁存或物理急停。[Collision Monitor 官方文档](https://docs.nav2.org/jazzy/configuration_and_development/configuration_guide/core_servers/collision_monitor/configuring_collision_monitor_node/)。

## 后续实施顺序，尚未开始

1. 恢复可用基线发布包，建立完整 Flash 固化与冷启动记录；先验证网络、轮速、直行/转向与失联停车，处理仍可复现的低速起动问题。

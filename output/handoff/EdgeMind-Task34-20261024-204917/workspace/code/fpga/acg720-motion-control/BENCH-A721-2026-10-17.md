# A721 左轮起动与编码器故障，2026-10-17

用户自行运行 `python host/startup_test.py --port COM4 --wheel left`，明确反馈“可以转动但是转动一会d6 d4 d0就亮，电机就停止转动”。本轮代理未下载、未连接串口、未发送运动命令。

ARM后state=1/faults=0/PWM=0。1kHz、PI上限512、左目标400mm/s、右目标0、主机时限1秒。前13条RUN遥测：左计数0→1567，速度0→409mm/s（其间423），左PWM295→504峰值→384，右计数/速度/PWM全0。第14条：state=3、faults=2、左计数1736、左速度437、双PWM0、命令年龄59ms。Final：state=3/faults=2、左计数1785、左速度409、双PWM0、命令年龄76ms。起动及反馈活动已有用户与遥测证据；这不是连续运行、双轮方向、停距或闭环精度验收。

faults=2即bit1：任一路编码器出现非法AB转换（00↔11或01↔10），或已有累计非法计数。D4=此故障，D6=FAULT，D0=复位释放，不是三个独立故障。当前遥测不报告左右非法计数，不能确定来自左还是右；不能仅由本日志确定噪声、接触、供电或解码问题。现有解码器为三级同步，没有稳定时间滤波，任一非法跳变即停车；本轮未修改或屏蔽保护。

停后计数继续增加、速度非零与滑行状态相容，不证明桥仍输出。Final只确认内部PWM为零，不是物理转动已经停止。

收尾另外报 `Cleanup incomplete; disconnect VM: No matching STATUS; test aborted`。源码发现run_motion最后发STOP后不读其回复，而send_and_read此前收到任意有效帧便提前返回，可能把旧STOP回复当作新请求的读取结果；本日志缺少原始序号，不能断言现场一定由此造成。现修复为等到当前序号的STATUS才提前结束，增加旧STOP先到/只有旧回复两项测试。原16项加新增2项，共18项Python回归通过。本修复仅Python，无需重烧A721。

下一步先断VM，确认静止后STATUS；断电检查编码器线束、接触及其与动力线的布置。故障源左右尚待细分，不能据此判驱动损坏。CLEAR_FAULT未清累计非法计数，可能立即再次锁故障；不能循环clear-fault绕过。需要重新测试时先在VM断开下S0复位，重新配置参数（startup_test会执行），而不是复位后直接沿用旧参数运行。再次带VM前先解决或缩小反馈异常范围。

# 任务3、任务4：FPGA 实时避障与自主导航

2026-10-24。按用户提供的任务图片实施基础功能，只使用现有 ACG720 FPGA 和内部软核，不需要 Linux、ROS 或外部计算机执行导航。外部界面用于人工建图、设置起点、选择目标/路径点、观察视频、日志及停止。

## 从完整 3D 模型提取几何

使用 `model/chassis/v4-lidar-imu` 的完整装配、保存的精确 B-rep 回读报告和参数，交叉核对 V5 完整装配。两个版本的 XY 包络、驱动轮与雷达位置一致；不再借用 180×254 mm 的下壳 STL 作为整车尺寸。

- 原完整模型包络约 290×240.202×198.281 mm，包含轮胎、摄像头镜头、雷达等突出物。
- 模型坐标前方为 −Y；导航坐标前方为 +X、左方为 +Y。驱动轮轴线约为 CAD Y=60 mm，LD06 中心在 (0,−104)，因此雷达相对轴中点前偏 164 mm、横向偏移 0。
- 模型轮胎包围盒中心距约 214.161 mm，与用户实测轮距 234 mm 不同。保留 234 mm 作为运动学轮距，并在模型左右外廓各增加约 9.9195 mm，避免缩小车轮碰撞包络。最终保守导航矩形为前 221、后 70、左右各 131 mm，旋转半径向上取整为 257 mm。
- CAD 光学窗口高度范围约 185.681～198.281 mm，未将该区间的下沿伪称为精确激光扫描平面。当前二维投影只使用 XY，Z 偏移不参与运算；低矮、透明及扫描平面外障碍不在本次能力范围。
- `navigation_geometry_verified=true` 表示上述 CAD 基准与配置已核对，`physical_geometry_verified=false` 明确保留实物差异未验收。源码/参数/两个 STEP 的 SHA-256 已记录，模型若更改需要重新提取和构建。

复现入口为 `scripts/geometry_from_model.py`。模型中的线束、参考摄像头镜头和轮距与实物可能存在差异；这些边界不会因为 CAD 计算成功而自动成为实测通过。

## 任务3：检测、减速、停车与绕障

LD06 每点经过 CRC/有效性处理及坐标投影后，在 FPGA 内计算车体净空。前方判断覆盖车宽及横向裕量，前向距离扣除前外廓，后向距离扣除后外廓。这样使用的是障碍到车体的距离，而非仅用雷达原始距离。

完整有效扫描才授权运动，扫描至少覆盖 12 个角区与足够有效点，300 ms 过期撤销授权。新出现的近点不等待下一整圈才停车。当前初始参数为净空 250～600 mm 限速、≤250 mm 停车；这组参数仍须用实车制动距离与完整延迟验证。不同左右轮速的曲线/旋转还需满足包含车体旋转半径与裕量的全周净空，保守使用方形距离界限。

限速缩放采用定宽流水计算，默认导航范围100/350约分为2/7；路径跟踪的3/5速度上限与转向乘法分别分级。跟踪器使用寄存后的速度上限，安全模块使用最终门控前的目标方向，避免把位姿门控、方向判断、净距选择和跟踪限幅串成一条长路径。≤250mm硬停车与最终电机输出禁止不等待这些流水寄存器。定向仿真逐毫米核对默认及自定义阈值、全部1024种速度输入和左右弯道结果。

任务运行中遇障，独立保护先关闭驱动输出，导航目标保持为零；停车约 300 ms，记录新障碍到栅格，再进行膨胀和 A* 重规划，重新获得可靠定位与足够转向空间后跟踪新路径。每段最多 7 次重规划，不能绕过则结束并停车。坏包、断流、IMU/编码器故障、CPU 失效与人工 STOP 不按普通障碍自动恢复。

手动模式保留遇障锁存停车；自主任务中的有效近障碍允许有限停车重规划。两者均不能绕过最终硬件输出禁止信号。未知格、占据格和膨胀区不作为可行路径，禁止对角穿过障碍角点。

## 任务4：起终点与路径点任务

保留已实现的人工探索建图、冻结/上传地图、人工设置初始位姿、局部定位、单目标 A* 和路径跟踪。在此基础上新增最多 16 个有序路径点，由软核逐点提交目标，等待硬件到达后再切换下一点。通常可使用任务要求中的 3～5 个路径点。单段最多 120 秒，无进展/超时、定位或传感器故障会停车，不自动清错或重试 ARM。

上位机在“FPGA地图 / 导航”页选择“添加路径点”，在地图上按顺序点击，设置对应朝向，再点击“执行路径点”。紫色序号标示任务顺序，“清空路径点”只在界面空闲时操作；“取消 / 停止”继续使用原 STOP 流程。单目标及返回起点的旧入口保留。

执行前要求匹配的完整固件、配置 CRC、有效地图、初始位姿、可靠定位、IMU 校准和有效雷达。任务不自动从上电开始，也不在断电恢复后自动 ARM。地图与用户路径点当前需从文件/界面恢复。

明确启动多路径点任务后，板内软核提供控制租期；上位机查询只是进度显示，因此拔掉计算机不再等同于自主任务失效。人工/旧单目标模式仍保留原外部命令租期。STOP、物理停止输入、CPU 100 ms 心跳看门狗和传感器/电机故障始终优先。上位机工作线程在取消、异常或任务结束时也会发送 STOP。

## 软核固件与协议

`firmware/mission.c` 为裸机任务循环，`start.S` 和 `link.ld` 定义启动及 8 KiB 片内内存。使用现有 Zig 0.13.0 的 RV32I C 工具链，显式使用 `generic_rv32`，没有浮点、压缩、乘除扩展或系统调用。构建输出的 `mission.hex` 初始化 BSRAM，完整 `.fs` 包含该初始化内容，固化到外部 Flash 后一起保留。

构建：`../.venv/Scripts/python.exe -X utf8 scripts/build_mission.py`。主 FPGA `scripts/build.py build --fusion --tft480 --route-option 2 --place-option 1` 会先重建固件、把初始化镜像复制到构建目录并记录哈希。时序诊断先运行`scripts/build.py synth --in-place --fusion --tft480 --route-option 2 --place-option 1`，记录综合估算频率与关键路径；检查后可用同参数的`pnr`模式复用已核对全部输入及哈希的网表，避免重复综合。综合估算不等于整板布局布线签核。

新增 EMC1 内部命令 `0x58`，回复类型 `0xD0`、32 字节。请求首字节为操作，追加路径点时后接 `x格号 uint8、y格号 uint8、终点航向 uint16`，小端。格号范围 0～127，地图分辨率 50 mm，原点 (−3200,−3200) mm；航向一周为 65536。

| 操作 | 载荷长度 | 行为 |
| --- | --- | --- |
| 0 | 1 | 空闲时清空板内任务 |
| 1 | 5 | 空闲时追加路径点，最多16个 |
| 2 | 1 | 已 ARM 且几何条件有效时启动；不自动 ARM |
| 3 | 1 | 取消，硬件立即撤销软核所有权 |
| 4 | 1 | 只读进度 |

回复 byte0 为拒绝/错误码；byte1 的 bit0/1/2 分别为任务活动、CPU 心跳有效、CPU 故障；byte4/5/6/7 为已完成点数、总点数、内部阶段、任务错误。进度快照可能相差一个固件循环，不能作为物理到达的独立测量。

板内 CPU 与外部地图/导航控制通过显式所有者仲裁，任务执行期间不接受外部更改地图、起点或目标。手动轮速不能抢占自主任务。CPU 不直接访问 PWM，任务和最终电机安全始终分离。

## 已确认的 J1/FPC 屏幕

用户确认接的是4.3寸 RGB 屏，接口按仓库 AT043TN24-V1 规格与开发板引脚资料实现。原有摄像头采集、DDR3、HDMI 和网口视频保留；本次小屏先用于参数页，不在该屏上缩放摄像头图像，也未启用触摸。

参数页使用12行、每行32字符，字体12×16像素，避免将正负数拆到两行。显示运动模式/停车原因、轮速目标和反馈、姿态、TOF有效性、前方车体净距及左右雷达距离、位姿、航点进度、CPU心跳、导航原因、匹配质量、几何状态、相机/DDR/网口状态。未连接的TOF显示STALE，不伪造测量值。GEO READY仅对应已核对的CAD导航参数，不代表实物测量通过。

显示格式化先寄存字段值，再进行符号/幅度和十进制转换；小屏字符位置译码另加一级寄存。小屏坐标在连续两个像素采样间至少保持5个系统时钟，因此流水结果在下降沿输出前已稳定；HDMI仍使用原像素延迟。流水改动后的完整参数页与改动前逐像素一致，已用RTL帧输出比较。

| 信号 | FPGA球位 |
| --- | --- |
| PCLK / DE / HS / VS / BL | AB20 / AB22 / V19 / Y19 / AB21 |
| R[4:0] | N14 P16 R17 N15 L6 |
| G[5:0] | T18 N17 P17 P15 R16 N13 |
| B[4:0] | U17 U18 P14 R14 R18 |

时序525×286，HS低41像素、VS低10行，后沿均2；PCLK平均9 MHz、帧率约59.94 Hz。利用50 MHz时钟使能生成40/60 ns半周期，在下降沿改变数据、上升沿采样，逻辑仿真保证最小40 ns数据建立时间，输出布线另限制10 ns，整板还需实际STA及屏幕测试。背光延迟6帧约100 ms。此处不把RTL仿真裕量当成板端测量值。

完整开发入口 `../dev.cmd -Action build -Project fusion` 默认包含此屏；产物放 `.local/gowin-fusion-tft480`，与旧的无屏构建分开。复现回归可使用 `../.venv/Scripts/python.exe -X utf8 scripts/check.py --wsl Ubuntu-26.04`，WSL运行官方Icarus 12的RTL仿真，Windows Python继续验证原上位机和DLL。

较大的`cad_navigation_tb`使用完整CAD外廓、257mm旋转半径和164mm雷达前偏，在3×2.4m合成房间中验证定位、暂停、重规划和恢复转向。该场景已分别用Icarus和Verilator运行通过；完整WSL回归中使用已安装的Verilator编译此场景，其余夹具保持Icarus，并逐项记录后端。该静态位姿夹具不提供连续车体运动或到达精度证据。

默认算法0的开发构建曾停在路由阶段，未形成最终结果。当前开发入口显式选择算法2；[高云SUG100手册](https://cdn.gowinsemi.com.cn/SUG100E.pdf)第40页说明该算法优先提高布线速度。保持原有时钟、时序驱动及hold修复，不通过放宽时序来换取构建成功。`result.json`在启动时即记录`run_state=running`、进程号、起始时间和全部输入哈希，结束后再写最终结果；报告生成器拒绝将运行中或被中断的旧记录当作验收通过。

算法2、默认布局的构建在路由阶段主动结束（约2343.5秒）以合入已验证的退出修复和约束核对，没有位流或最终时序报告。当前入口同时使用文档第39页的布局算法1，优先可布通性。`axis_async_fifo.v`中的Gray指针、请求/确认和状态翻转的第一级同步器加入8ns路由上界及仅针对该级的hold例外；提交指针的二进制总线只在请求到确认期间保持，并在两级请求同步后采样，因此单独限定该保持总线。没有切断整个时钟组，也没有排除后续同步逻辑或未知DDR校准路径。

## 验证与固化边界

整板综合诊断还发现原视频采集及帧缓存使用了过宽的内部计数器。共享`dvp_capture_continuous.v`按图像像素数和热身帧数设置宽度，异常长帧饱和在无效像素总数，防止回绕；`ddr_framebuffer.v`按每帧像素/块数设置宽度，单个在途读请求使用一位状态。保留视频接口、图像格式、双缓冲、DDR背压和所有原接线。完整回归包括新增采集异常夹具及原工程`ddr_framebuffer_tb`，分别验证坏帧丢弃、独立命令/数据阻塞、顺序像素与显示缓冲保护。

最终本轮结果见 `verification/TASK3-4-RESULTS.json` 与 `verification/TASK3-4-REPORT.md`。旧 `FUSION-RESULTS.json` 是较早版本记录，不能当作当前新增软核后的结果。

验证覆盖真实 RISC-V 指令启动、三个路径点的顺序与完成、CPU 卡死看门狗、无外部心跳运行、车体净空、障碍减速/停车、静态绕障路径、完整合成房间定位/重规划、取消/失联及视频/网络现有回归。合成扫描、理想响应和任务桩不等于实车跑通；完整录制回放、精度、制动距离、视频满负载实车长测、实际 Flash 固化及真正断电重启均须单独记录。

`mission_navigation_tb`还在实际`a741_core`中联合运行软核固件、仲裁、合成房间定位、A*与跟踪器，验证三个邻近航点、无上位机心跳和执行时禁止改图。它发现并回归覆盖了压缩路径中负X/负Y方向被零扩展的问题，以及上一段到达标志尚未清除便取消下一段规划的问题。此夹具的三个终点均在到达容差内，用于验证真实模块间切换，不作为连续车体动力学或到达精度测试。

电机层另外验证正常释放自主控制权时优先结束ARM会话、清零目标和禁止输出，不把已过期的外部租期误记为故障；该结束动作优先于同周期的ARM/轮速包。自主权仍存在而软核租期失效时，原超时停车和故障锁存继续生效。PNR缓存复用也核对软核初始化镜像等全部综合输入，不能只比较Verilog源码而遗漏固件变化。

不覆盖原稳定 `130843`，也不把本次重新编译产物称为该稳定包。新位流通过全部交付条件后，使用仓库 `scripts/fpga/program_flash.py` 完整写入 Flash，不能只下载 SRAM。当前尚未通过的项目必须保留为未完成状态。

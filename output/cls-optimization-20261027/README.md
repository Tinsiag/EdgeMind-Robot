# 2026-10-27 基础功能精简与 CLS 优化

当前唯一产品范围由用户在本轮继续修正：

- OV5640 480×272 RGB565 → DDR3 完整帧双缓冲 → J1 480×272 TFT。
- IMU 姿态采集与横滚、俯仰、偏航实时文字叠加；雷达距离、避障与故障状态。
- LD06 扇区基础避障；必要的编码器闭环、ARM/STOP、租约与内部裸机软核监督。
- Ethernet 仅传设置/遥测/调试数据，不传摄像头视频。
- 删除 HDMI、网口视频 FIFO/打包器、地图、A*、定位/匹配、航点及对应上位机入口。

用户要求布线停止。仅做源码、离线验证和综合，不自动恢复 PNR，也不烧录/ARM。

## 原始现场

`baseline/result.json` 是被用户停止的上一轮完整构建原始记录，保留原字节。脚本通用状态 failed 源于人工结束工具进程；实际应按 `USER-STOP.json` 理解为 interrupted_by_user。最后确认 Routing Phase 0 完成，2859.48 秒，非超时。没有新位流和最终拥塞/时序报告，不能把推测写成唯一布线根因。

原综合计数 LUT35153、REG27235、ALU5195、BSRAM81。仅 autonomy 层级 LUT7110/BSRAM34；两路 OSD LUT4394/REG3398，外加视频 OSD 跨域。主时钟综合估算52.725MHz/目标50MHz，125MHz域估算126.155MHz，余量小。综合估算不是最终时序。

`PRUNE-MANIFEST.json` 记录从本机另一现场只复用基础避障代码的来源/哈希；没有复用其800屏驱动、接线、旧验收或烧录结果。`pre-prune/` 和 `baseline/source/` 保存移除前代码，不在活动工程编译路径。

## 采用的方法与原厂资料

- https://cdn.gowinsemi.com.cn/SUG113E.pdf （v1.3，2025-04-30）：层级资源分析、时序/面积权衡、高扇出/拥塞。
- https://cdn.gowinsemi.com.cn/SUG550E.pdf （v2.4，2026-06-17）：寄存器/RAM/DSP 推断和综合报告。
- https://cdn.gowinsemi.com.cn/SUG949E.pdf （v2.2，2026-06-17）：RAM、寄存器及运算编码示例。
- 本机原厂 UG303-1.0E：Arora V 每 CLS 两个 LUT/两个 FF；CLK/CE/SR 和打包限制。因此 LUT 数不能直接换算为 CLS。
- 本机 SUG1220-2.1E：公开 run 步骤为 syn/pnr/all，没有声称存在已验证的只布局命令。

先删除不在当前范围的硬件，减少数据搬运与时钟域；TFT像素用50MHz域/10的使能推进，屏幕仍固定5MHz、525×286，DE起点42/11，100ns逻辑setup/hold。显示工作缓冲不挂复位树，数值位置不重复清空；只有完整构建并到达帧空白才发布。参数及电机发布锁不因优化解除。算法1/布局1、时序驱动和hold修复保留。

曾对原双OSD局部综合试验得到 LUT4478→4004、FF3836→3727；原版90,000周期等价测试通过。此后用户明确改为单路摄像头TFT叠加，最终版本应看新的整板综合，不能把该旧局部数字冒充最终结果。

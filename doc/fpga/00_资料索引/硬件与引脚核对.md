# ACG720 硬件与引脚核对

本表根据目录内的通用原理图、引脚 XLSX 和教学工程交叉整理，适用于理解这套 PG484A 板级资料。尚未核对实物板卡版本，也未进行电气测量、编译或上板验证。引脚均指 FPGA 封装球号；`I/O` 方向均以 FPGA 为参照。

原始依据：[主板原理图](<../06_hradware/acg720-138-60k-tong-yong-yuan-li-tu.pdf>)、[引脚工作簿](<../04_IOmessage/gowin-acg720-138-60k-generic-pin-assignment.xlsx>)、[保留 Excel 行号的原始引脚 CSV](原始引脚表.csv)。CSV 保留原表错误，下面单独说明核对结果。

## 时钟和基础接口

下表逗号分隔的球号与信号编号顺序一一对应。LED 和按键有效电平已结合第 10 页电路核对。

| 信号 | FPGA 球号 | 方向／说明 |
| --- | --- | --- |
| 系统时钟 `FPGA_GCLK1` | Y18 | I；50 MHz 有源时钟 |
| `LED0,1,2,3,4,5,6,7` | M22,N22,L21,K21,K22,J22,H22,M21 | O；高电平点亮，共 8 个用户 LED |
| `SW0,1,2,3,4,5,6,7` | G22,D22,E22,G21,E21,D21,C22,B22 | I；拨码开关 |
| `S0,1,2,3,4` | F15,A20,B20,A21,B21 | I；按下为低；复位选择由工程决定 |
| `FPGA_UART_RX` | J21 | I；接收 CH340E 发来的数据 |
| `FPGA_UART_TX` | M15 | O；发送给 CH340E |
| 红外 `IR` | F21 | I |
| 蜂鸣器 `BEEP` | N19 | O；原表的 LED8/N19 是重复误标 |
| I2C `SDA / SCL` | M16 / M13 | SDA 双向；SCL 依控制器实现；板载 EEPROM、RTC、音频配置共用 |
| 74HC595 `DIO / RCLK / SCLK` | M18 / C2 / F4 | O；串行数据、锁存、移位时钟 |
| ADC `CS_N / DIN / SCLK` | M6 / M5 / N5 | O；DIN 在图中称 `ADC_SADDR` |
| ADC `DOUT` | P6 | I；图中称 `ADC_SDAT` |
| DAC `DIN / SCLK / CS_N` | P5 / P4 / P2 | O |
| MicroSD `CMD / CLK` | N4 / N3 | CMD 双向，CLK 输出 |
| MicroSD `DATA0,1,2,3` | R1,P1,J5,K6 | I/O；本套教程没有独立完整 SD 实验 |

引脚表第 27 行把 S4/B21 标为复位；第 29 章 `src/gao_hdmi_color.cst` 第 28 行、以及第 65 章 `src/FX2_Loopback.cst` 第 64 行则使用 F15/S0。不能仅凭工作簿确定当前实验的复位键。UART 的波特率也应看具体 RTL／上位机配置，视频和 PDF 示例并不全部相同。

## TFT、触控和 HDMI

| TFT 信号 | FPGA 球号 | 说明 |
| --- | --- | --- |
| `PCLK / DE / HSYNC / VSYNC / BL` | AB20 / AB22 / V19 / Y19 / AB21 | O；对应时钟、数据使能、行同步、场同步、背光 |
| 物理 `LCD_R[4:0]`，从 R4 到 R0 | N14,P16,R17,N15,L6 | O；5 位红色 |
| 物理 `LCD_G[5:0]`，从 G5 到 G0 | T18,N17,P17,P15,R16,N13 | O；6 位绿色 |
| 物理 `LCD_B[4:0]`，从 B4 到 B0 | U17,U18,P14,R14,R18 | O；5 位蓝色 |
| `TP_INT / TP_SCL / TP_SDA / TP_RST` | P20 / T21 / T20 / Y21 | 第 1、11 页所示触控信号；原引脚表没有独立列出此组 |

**物理颜色通道固定，RTL 的总线打包可以不同。** 第 28 章 `src/tft_ctrl.cst` 第 20 行将 `TFT_rgb[15]` 放到 N14，即红色最高位；第 38 章 `src/uart_ddr3_tft_hdmi.cst` 第 128 行则将同名位放到 U17，即蓝色最高位。第 45 章采用后一种方式。检查过相应 RTL 与 CST 的配套关系，这种位序差异本身不能判定为错误。

| 工程／资料 | 红色 | 绿色 | 蓝色 |
| --- | --- | --- | --- |
| 第 28 章 | `TFT_rgb[15:11]` | `[10:5]` | `[4:0]` |
| 第 38、45 章及引脚工作簿 | `TFT_rgb[4:0]` | `[10:5]` | `[15:11]` |

移植时应同时核对像素格式、RTL 输出拼接和 CST。配套 4.3／5 英寸模块资料以 800×480 为主；第 28 章也讨论 480×272。分辨率、像素时钟和消隐参数要使用同一套配置。

| HDMI 信号 | HDMI1 球号 | HDMI2 球号 |
| --- | --- | --- |
| CLK P / N | K4 / J4 | H4 / G4 |
| DATA0 P / N | L3 / K3 | E2 / D2 |
| DATA1 P / N | L5 / L4 | F3 / E3 |
| DATA2 P / N | M3 / M2 | H3 / G3 |
| OE | H5 | K2 |
| HPD | M1 | N18 |
| DDC SCL / SDA | N2 / J6 | L1 / K1 |

OE 在第 7／8 页中控制 HDMI 电源与相关电路，是普通控制信号。工作簿第 65～83 行把 HDMI 信号（包括 OE）统写成 `TMDS_33`，而第 29 章配套 CST 使用 `LVCMOS33`。这些是原资料的不同写法，不能直接把工作簿电平列转换成可用的 Gowin 约束；具体发送原语、板级终端、驱动和工具规则应结合工程核对。本次未验证信号完整性。

教程的 `dvi_encoder` 主要实现 TMDS 视频传输。具有 HDMI 连接器并不代表例程已经实现音频、CEC、HDCP 等全部 HDMI 功能。

## OV5640 摄像头

| 信号 | FPGA 球号 | 方向／说明 |
| --- | --- | --- |
| `D0,1,2,3,4,5,6,7` | J2,J1,G1,H2,F1,G2,D1,E1 | **I**；摄像头向 FPGA 输出像素字节 |
| `PCLK / HREF / VSYNC` | B1 / A1 / B2 | **I**；摄像头提供采样时钟及行帧同步 |
| `XCLK` | M17 | O；FPGA 提供摄像头参考时钟 |
| `RESET` | N20 | O；摄像头复位 |
| SCCB `SDA / SCL` | L18 / M20 | SDA 双向；SCL 由 FPGA 控制器产生 |
| `PWDN` | 原理图未连接至 FPGA 球号 | 第 11 页 P4 的 18 脚经 R136（4.7 kΩ）下拉到 GND |

原工作簿第 86～93、95～97 行把摄像头数据和同步标为 O，应根据采集方向理解为 FPGA 输入；`COMS` 也是原表中的拼写，原理图使用 `CMOS`。

**第 45 章 `camera_pwdn` 约束与原理图冲突。** 138K 包 `ch45_ov5640_ddr3_tft.rar` 内 `src/ov5640_ddr3_tft.cst` 第 150 行写 `IO_LOC "camera_pwdn" L1;`，`src/camera_init/camera_init.v` 第 61 行将其固定为 0。主板第 2 页则明确 L1 为 `HDMI2_SCL`，第 11 页摄像头 PWDN 由电阻下拉。该示例约束不能作为摄像头 PWDN 的实际连线依据；若按本图制作的板卡同时使用 HDMI2 DDC，需要处理这一冲突。没有据此修改原例程。

ACM5640-V5 目录内说明文件与用户手册对补光／自动对焦能力的描述不一致。目录说明明确写 V5 没有这些硬件支持，用户手册却仍含相关功能文字，应以模块实物及对应版本原理图确认。

## 以太网和 USB2.0

| RGMII／管理信号 | FPGA 球号 | 方向 |
| --- | --- | --- |
| PHY `RESET` | V22 | O；低有效复位 |
| `RXCLK / RX_CTL` | W19 / AB18 | I |
| `RXD0,1,2,3` | V17,V18,P19,R19 | I |
| `TXCLK / TX_CTL` | U22 / AA19 | O |
| `TXD0,1,2,3` | U21,W22,W21,Y22 | O |
| `MDIO / MDC` | W17 / AA18 | MDIO 双向，MDC 输出 |

原表第 130 行将 `E_TXC/U22` 标为输入。原理图对应网络是 `E_GTXC`，进入 PHY 的 TXCLK；RGMII 示例由 FPGA 的 ODDR 产生发送时钟，因此是 FPGA 输出。图上的 `E_TXEN/E_RXDV` 名称在 RGMII 中分别承载 TX_CTL/RX_CTL，不能完全照搬普通 GMII 的单沿解释。

| FX2 SlaveFIFO 信号 | FPGA 球号 | 方向／说明 |
| --- | --- | --- |
| `IFCLK` | L19 | I；资料示例采用 FX2 提供接口时钟的配置 |
| `SLCS / SLOE / SLRD / SLWR / PKTEND` | J16 / J15 / K19 / L20 / J14 | O；具体极性由 FX2 固件配置配合 |
| `FIFOADR0 / FIFOADR1` | K13 / H13 | O；选择端点 FIFO |
| `FLAGA / FLAGB / FLAGC` | H17 / H18 / J17 | I；标志含义由 FX2 固件配置 |
| `FD[7:0]`，从 FD7 到 FD0 | G15,K14,G16,G13,J20,G20,G17,G18 | **I/O** |
| `FD[15:8]`，从 FD15 到 FD8 | H19,J19,K17,K18,L16,K16,L15,L14 | **I/O** |

原表第 149～164 行把 USB FD 总线全部标成 O。SlaveFIFO 回环中 FPGA 既读取也写入，该总线需要三态和方向控制；单向实验也必须与 FX2 输出使能配合。CH340E 串口与 FX2 数据传输使用不同器件和协议，调试时按实验选择对应 USB 功能。

## DDR3、音频和 GPIO 扩展

DDR3 原理图采用 **MT41K128M16JT-125:K，128M×16 bit = 2 Gbit = 256 MiB**。主板第 12 页的 DDR 电源是 1.5 V，原引脚表 DDR 部分使用 SSTL15／DIFF_SSTL15。虽然 MT41K 属于 DDR3L 器件，其配套手册明确包含 1.5 V 兼容条件，不能只凭 DDR3L 字样推断本板供电是 1.35 V。

DDR 的全部地址、数据、DQS、DM 和控制球号见原表第 170～217 行，并对照主板第 1、4 页。开发时以对应器件和封装的 DDR PHY/IP 配置为整体核对对象，不能只更改 `.gprj` 中的器件名称。第 36 章含其他封装的官方参考工程，第 37 章提供板级双端口控制器应用。

| ES8388 信号 | FPGA 球号 | 说明 |
| --- | --- | --- |
| `MCLK/XCLK` | V20 | 示例由 FPGA 提供主时钟 |
| `BCLK / LRCK` | U20 / W20 | 方向取决于编解码器主从配置；原表按输入列出 |
| `ADCDATA` | AA21 | I；编解码器 ADC 数据进入 FPGA |
| `DACDAT` | AA20 | O；FPGA 数据送给编解码器 DAC |
| 配置 `SDA / SCL` | M16 / M13 | 共用板载 I2C 总线 |

GPIO0 在 P7 上提供 36 根信号，完整映射见原表第 219～254 行及原理图第 11 页。VCCIO 可选 3.3/2.5/1.8/1.5 V；接口还包含电源与地脚。连接外接模块时需要区分 FPGA 信号电平和连接器的供电脚，并按实际 VCCIO 设置约束。

原表后半部另有 ACM7606、ACM1030、AD9767、ACM9238、ACM2108、VGA 模块对 GPIO0 的映射。它们占用同一个扩展口的不同接法，不是多组相互独立的板载 IO。配套图纸集中在 [模块原理图目录](<../06_hradware/dev-board-compatible-modules/>)，未覆盖上述每一种型号；具体文件见 [PDF 目录](PDF目录.md)。

## 器件与模块资料的版本差异

| 对象 | 原理图／配套资料差异 | 使用时的处理 |
| --- | --- | --- |
| 以太网 PHY | 第 6 页 U11 为 **RTL8211F-CG**；附带独立手册主要是 RTL8211E/EG；原 SchDoc 文件名也保留 EG | 寄存器页、延迟配置及上电绑定位要核对 F 型号手册 |

# A745 片上自主避障

2026-10-30 新活动工程。应用控制、摄像头初始化、DVP 帧采集、网口发送与主机入口已重构；旧版本只在来源清单和Git历史中记录，活动目录已清理。验证与烧录结果以仓库根目录 `HANDOFF-20261031.md` 和 `output/refactor-autonomous-20261030/` 为准。

## 操作

上电不 ARM，四路电机输出零。S1 必须先释放，再新按一次，启动 LD06 和静止校准；IMU、编码器、完整雷达扫描、CPU 和几何检查都通过后进入自主避障。再次按 S1 停止；S0 硬件复位会立即撤销许可。故障锁定，不自动恢复运动。

旧测试固件的“GND锁”是FPGA内部固定低电平，A745已解除；不要为此拆掉公共地。左轮LAIN1/2对应A18/A19，右轮RAIN1/2对应F13/F14。VM关闭、完全断电时核对原接线；轮子架空、小车静止、停止条件可用后才给VM上电，短按S1校准启动。先验收架空轮子和停止，再做低速落地避障。

FW74504按用户最新要求，将前方停车线设为屏幕F≤500mm。F>800mm巡航120mm/s，501～800mm减速至60mm/s，不在1m处停车。前方触线后停轮100ms，选择距离≥600mm且车身转弯包络安全的一侧；两侧都可走时选更远一侧，两侧都不通就保持BLOCK等待，不自动倒车。距离是雷达原点读数，不是车头外壳到障碍的距离。实际烧录/验收状态见根目录交接，不将旧版本验收套用给新SHA。

左右转空间由当前CAD车身轮廓和雷达安装偏置分别计算0～90度扫掠凸包，包含40mm几何余量及离散角度/查表保守预留；不再用全周521mm门槛封锁所有转弯。每个雷达点可立即撤销对应转向许可，缺扫描覆盖、低置信度和过期扫描不能放行。几何检查是CAD模型验证，未替代实车制动、安装偏差和低矮障碍验收。

转弯以陀螺仪相对航向90度为目标，按角度余量将轮速由80mm/s降至40mm/s，约87度进入停车制动，再停稳150ms。前方达到600mm后恢复直行并锁定实际新航向；仍堵塞则等待重新择路。直行由航向反馈、左右轮速同步及每轮速度PI保持。当前没有卡尔曼滤波，也不宣称相对航向没有长期漂移。转弯4.5秒未达到目标或航向明显反向时ERR0080锁存停车，传感器、倾斜、CPU和编码器故障仍优先。

旧FW74503的ERR0020来自受限空间恢复失败；新版将普通障碍等待与硬件/传感器故障分开。用户已确认旧版可前进并识别前障停车，但转弯新版必须单独验收。先关VM再移动车身，轮子架空且停止条件可用后开启VM，短按S1测试；再按S1停止。

## 屏幕和摄像头

屏幕沿用已能显示文字的 800×480 / 33 MHz 接口，AB22=DE、AB21=背光。摄像头仍为 P7 TY-OV5640 自带晶振接法，未套用原厂 P4 XCLK 接线。

- 一个 SCCB 总线引擎执行完整初始化，采用原厂第45章字节/位驱动。
- 上电等待 100 ms，物理复位 2 ms，释放等待 25 ms，软件复位后等 5 ms；关键寄存器逐项回读，最多四次完整物理复位尝试。
- DVP 数据、HREF、VSYNC 同束延时和寄存，只提交完整有效 RGB565 帧；不从半帧开始显示，坏帧不提交。
- 文字按实拍可见范围480×272排布，两条深色状态栏、每行32列、2倍字形并保留边距，摄像头仍维持800×480采集/扫描。正常页显示ARM/IMU/CAM、R/P/Y角度、F/L/R距离、MODE/NET/ERR；R/P/Y为roll/pitch/yaw，F/L/R为前/左/右。青色正常、黄色等待、橙红故障。摄像头失败时下栏切换为 `CAM:xx REG:xxxx READ:xx`，分别是错误码、寄存器、实际读值。`00` 表示没有错误，`01` 写 NACK、`02` 读 NACK、`03` 事务超时、`04` 回读不符。初始化阶段与尝试次数可在遥测中看到。

离线通过不等于实屏和冷启动通过，实际观察必须另记。

| LED | A745 含义 |
| --- | --- |
| D0 | 系统及显示时钟锁定 |
| D1 | 摄像头初始化和回读成功 |
| D2 | PHY 初始化成功 |
| D3 | DDR 初始化完成 |
| D4 | 至少一帧完整视频可显示 |
| D5 | 摄像头初始化失败或视频 DDR 错误 |
| D6 | 视频输入溢出 |
| D7 | 运动故障 |

## 网口

只发送 EMS1 状态、EMF1 姿态、EML1 雷达数据。源 `192.168.0.2:6103`，目标 IPv4 / MAC 广播、UDP 6103；状态和姿态每 100 ms 发送一次。无 Ethernet RX 引脚/接收模块、ARP 缓存、控制命令、配置下发、ARM、心跳续约或网口视频。PHY 的 MDIO 初始化保留，用于建立物理数据链路。

电脑直连网卡设为 `192.168.0.3/24`，运行本目录 `launch.cmd`，点击“接收遥测”。窗口只收数据，不能通过电脑启停车辆。链路断开不改变本地自主避障会话。

EMS1 长度 112 字节，小端。相比历史包，68..71 是 `{寄存器16,期望8,实读8}`，80..83 是视频帧计数，98 是摄像头错误码，99 的位 6..3 为阶段、2..0 为尝试次数；阶段 11 为成功、12 为失败。必须使用本目录接收器，不能用历史控制客户端解释这些扩展字段。

FW74504增加104..105后方距离、106的bit0/bit1分别为左/右CAD转弯许可、107为完整扫描序号；长度和版本保持不变。MODE 9为SETTLE，表示转弯后停稳，随后才恢复直行。许可来自几何包络，实际转向还要该侧通路距离满足600mm。

## 构建

在仓库根目录运行：

```powershell
code/camera-car-control/.venv/Scripts/python.exe code/camera-car-control/a745-autonomous/scripts/check.py
code/camera-car-control/.venv/Scripts/python.exe code/camera-car-control/a745-autonomous/scripts/build.py build --timeout 1800
```

RTL 仿真使用 WSL Ubuntu-26.04 的 Icarus / Verilator，EDA 为 Gowin V1.9.12.04，器件 GW5AT-60B / GW5AT-LV60PG484AC1/I0。固定布局1、布线1、时序驱动和 hold 修复，生成 STA/SDF/物理网表。`build.py` 不烧录，不把“生成 .fs”当作时序签核。

`rtl/` 为新应用，`lib/` 为已验证叶子驱动，`vendor/board/` 为原厂 PLL/DDR/TX IP，`constraints/` 为明确的活动约束。共享 `../third_party/verilog-ethernet/` 只使用 FIFO、GMII TX 和 CRC LFSR 三个文件。`REFERENCE-SOURCES.json`、`vendor/board/ORIGIN.json` 与每次构建的输入 SHA 记录来源，不依赖旧应用被忽略的 `.local` 缓存。

位流在 `.local/gowin-a745-autonomous/impl/pnr/a745.fs`，UserCode `0xA745`。烧录必须使用仓库 `scripts/fpga/program_flash.py`、明确 SHA，并完成 Flash54@0 写入/校验、Reprogram、只读就绪及 UserCode 比对；VM 关闭，不自动 ARM。

当前启动增量：PicoRV32通过PICORV32_REGS使用显式FF寄存器，维持两路组合读取；姿态valid表示最近发布的角度对，在正常新采样的CORDIC计算期间保持，坏/旧数据立即失效。FW74503包含这两项修复。专项综合网表CPU执行和真实姿态计算+自主会话联动检查均为烧录门槛。

当前FW74504已写入外部SPI Flash并校验，SHA-256为74cef81a075feb78f9c5bc70a91384a368dc81e080ad65a3eccbb867f01719df。遥测确认实际74504、CPU/摄像头/DDR正常，IDLE/ERR0000。新SHA真实冷启动及转弯待实物验收，旧74503验收另存历史记录。上电不会自动启动电机，仍需S1。烧录与验收记录见根目录output/refactor-autonomous-20261030/。

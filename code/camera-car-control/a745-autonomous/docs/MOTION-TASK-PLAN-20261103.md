# FW74512 后续运动与视觉任务规划

日期：2026-11-03。本文保留设计提案，基线为 FW74512，SHA `888761b35c206f21d920bb192c920d785f3606ed9b2b73b64ff488a354bf4256`。用户随后授权实施和Flash，已开发FW74513候选；实际实现范围与操作见 [README-MODES-AND-TARGET-74513.md](README-MODES-AND-TARGET-74513.md)，编译/Flash/实物状态以证据为准，本文中的规划项目不代表全部已完成。

本日需求收敛：寻物仅按网页选定的YOLO类别，不做颜色辨别；演示场景只有一个目标实例，不实现多目标身份选择。保留误检抑制、单目标时序连续性和相机—雷达测距关联，并优先选择两种传感器均能稳定观测的实物。

## 1. 已核实的问题与边界

- `rtl/a745_navigation_scan.v`：前方为±30°，左侧45～135°、右侧225～315°，各区取合格点的最小雷达原点距离；不是车壳净空，也不是通道宽度。
- `rtl/a745_autonomy.v`：左右转向需要对应扇区≥600mm和CAD扫掠包络安全同时成立。侧面一个500mm点就能否决该方向，即使实际转向轨迹可通行。这是保守误拒绝的明确来源。
- 后退仍要求前方≤300mm、左右不可选、后方>350mm、同一堵塞阶段尚未短退。单凭F/L/R均500mm不会触发后退。用户观察的约50cm后退需要捕获进入REVERSE前后的扫描、合格点、F/L/R/B、包络许可及判定原因；不能预先认定阈值错或传感器坏。
- 现有90°转弯后重新锁定新航向，没有保存原行进路线，因此当前是反应式择路，不具备绕过障碍后回线能力。
- 当前S1释放资格仅在低到高的消抖转换后建立，正常上电一直松开时首次按下被忽略；现有测试只覆盖上电按住场景，需补充正常上电场景。
- 当前仅约束S0/F15和S1/A20，没有活动数码管端口/约束。用户提供的 `doc/ACG720-138&60K通用管脚分配表.xlsx`（Sheet1，23～27、39～41行）确认S2/B20、S3/A21及74HC595数码管接口，均为LVCMOS33，与当前board.cst无引脚冲突。S0直接复位PLL和逻辑，继续用于复位停止。数码管串联位序、共阳/共阴、段码及位选极性仍需原理图/例程核实。
- 当前测距使用LD06，`TOF_ENABLED=0`，不能把超声波或TOF列为已接入。人员识别为person类别检测，不是身份识别。
- 新FW74512仅显示和被动健康验收通过；旧74511运动验收不能代替新位流运动验收。ERR0001根因仍未确认。

## 2. 固定的产品入口与视频基线

保留现有链路：FPGA摄像头/DDR/TFT → EV10 UDP6104、640×480 → 4A NPU640×384约5Hz → ED10 UDP6105 → FPGA绿色框与原HUD。网页目标15fps。本地800×480/33MHz、x+80框映射、HUD置顶及显示过期清框继续独立工作。

首版继续使用已验证的量化YOLOv5n，按实测准确率决定是否换模型。Docker只作为后续训练/导出/HHB量化构建环境；换模型仍需验证TH1520算子、量化精度、解码与真实吞吐，不把容器可运行当作NPU兼容。

### 模式和按键（推荐映射）

| 数码管模式 | 模式 | 按S1启动后的行为 |
|---|---|---|
| 1 | 自主绕障 | 保持出发航向，遇障绕行，具备条件时恢复原路线 |
| 2 | 原地旋转 | 完成一次约360°闭环旋转后停车，不自动接着直行 |
| 3 | 智能寻物 | 使用网页选定目标，搜索、确认、绕障接近、到达停车 |

- 待机短按S2：下一模式，循环1→2→3→1；短按S3：上一模式。长按只产生一次选择事件，切换模式不启动。
- 待机短按S1：消抖后的按下启动所选模式，无需长短按复用。
- 运行或校准时：S1消抖后的按下立即取消任务、停车；S2/S3不切换执行中的模式，也不排队到停车后自动切换。停止后必须完全释放S1再启动。
- S0始终复位停止；上电及复位不ARM，默认模式1。
- 修复上电已松开不能首次启动的问题；上电按住仍不得触发启动或选模式。
- 数码管显示模式，闪烁可表示准备中、常亮表示待机/已选；运行/任务阶段在原TFT状态栏显示。若位数允许，另显示运行状态或旋转角度。最终编码以实际硬件为准。
- 多个输入同时发生时停止优先。网页选模式/目标不能代替本地S1启动。

| 接口 | FPGA引脚 | 规划用途 |
|---|---|---|
| S0 | F15 | 保留当前复位停止 |
| S1 | A20 | 启动/停止 |
| S2 | B20 | 下一模式 |
| S3 | A21 | 上一模式 |
| SEG7_DIO | M18 | 74HC595串行数据 |
| SEG7_RCLK | C2 | 74HC595输出锁存时钟 |
| SEG7_SCLK | F4 | 74HC595移位时钟 |

表中S4/B21标注“作为复位按键”，本方案不重映射现有S0复位，也不占用S4。数码管应增加同步时钟使能驱动的移位/锁存模块，复位先消隐，不用新逻辑派生时钟；核实串联位数及位序后再实施。

### 启动体验

`上电初始化 → 待机选模式 → 短按S1 → 静止校准/完整扫描/健康检查 → 约1秒启动提示 → 执行`。

校准保留64个有效陀螺仪样本和约10秒超时；屏幕明确显示正在等待IMU、雷达、网络或目标配置。准备过程中S1可取消；选模式不使车轮转动。校准期间禁止以零散编码器step瞬时为零代替持续静止，补充一个有时限的静止确认窗口。模式3还要求有效任务配置和4A任务链路；模式1/2不依赖4A连接。故障仍锁存，重新启动不能掩盖持续故障，编码器累计故障按现有复位规则处理。

## 3. 雷达判定与倒车优化

将“附近有点”与“车体能否通过”分开：

1. 保留原F/L/R/B原始意义供诊断，新增车体坐标下的行驶走廊、可用宽度、净空和拒绝原因。
2. 雷达点按安装偏置转换到车体坐标，前进/后退检查车体扫掠走廊；转向检查当前CAD轮廓扫掠包络。候选出口还要验证转过去后的短段直行走廊。
3. 侧方600mm扇区最小值从唯一通路硬门槛改为候选通路几何判定；不能仅删除600mm或统一下调阈值。当前CAD全宽262mm，40mm每侧余量给出342mm的静态直线宽度下限，但这不等于最终可通行宽度，仍需加安装、定位和制动预算并实测。
4. 前方300mm雷达停车线和后方>350mm后退条件先保留为底线。新净空指标明确坐标原点，不能将300mm悄悄改成车壳距离。速度仍先用120/60mm/s上限。
5. 正常选择使用多个新完整扫描确认、释放滞回和方向保持，减少左右摇摆。近障撤销运动许可仍立即生效，不等多帧投票。
6. 只有前进和左右候选轨迹持续不可用，且后方扫掠走廊安全，才允许短退；目标仍为最多100mm/2秒、60mm/s，停稳150ms、同一堵塞阶段一次。未知空间保持停车。
7. 记录明确原因，如前方走廊堵塞、左转包络冲突、右出口太窄、后方未知，网页可叠加被拒绝的候选轨迹；不只显示BLOCK。

首先用真实触发回放核实50cm现象，然后验证走廊算法；保留弱反射细物体的专项测试，不能因降噪而宣称可检测所有物体。

## 4. 有路线记忆的自主绕障

模式1由FPGA执行有界局部绕障状态机，使用编码器累计里程和IMU航向维护短程二维位姿。原航向参考跨越绕障过程保存，不被每次转弯覆盖。

典型左绕流程：

`前进 → 前障停车 → 左转约90° → 横向驶出障碍宽度 → 右转恢复原航向 → 越过障碍 → 右转靠回原路线 → 左转恢复原航向 → 继续前进`。

- 左右都安全时优先左绕，左侧不可行则右绕，选定后保持该侧直至完成或确认失败。
- 第一版分两步验收：先实现绕障后恢复原航向，再在里程计可靠和回归走廊安全时完成回到原路线。恢复原航向不等于回线。
- 横移距离和越过距离由连续雷达几何、车身尾部余量和短程位姿共同决定，不固定“走50cm就转”。保留障碍轮廓/占据记忆，不把侧方暂时无回波当成已越过。
- 每一段先检查相应转弯及平移走廊，动态障碍出现即停车重评估；设置最大段长、总里程、总时间和重规划次数。
- 遇墙、U形死胡同或无法回线时进入受阻等待/失败，短退作为有界恢复，不无限绕圈。首版不是全局SLAM，不承诺复杂环境必达或精确回到原线。
- 新的按距离动作要求里程观测有效；无进展会使本次有界动作超时退出，不恢复已被用户取消的全局“编码器1秒无脉冲停车”。

## 5. 360°定点旋转

- 共用校准、雷达、倾斜、CPU、编码器和电机联锁。开始前检查全周旋转包络，不能沿用单次90°包络作为整圈许可；旋转过程中持续重评估。
- 对相邻IMU航向样本的±180°环绕差分进行有符号累计，目标累计360°，最后减速、制动、停稳；不使用“回到起始yaw就是一圈”判据，也不把16位90°目标直接乘4。
- 编码器差速作为进度交叉检查，异常方向/IMU跳变/失效停车。旋转速度先沿用40～80mm/s轮速限制，接近终点减速。
- 按轮距234mm、轮速80mm/s估算一圈至少约9.2秒，实际减速后更长；现有90°的4.5秒总超时不适用整圈。重新制定分段进度超时和整圈总超时，实测收敛。
- 完成后保持停车、显示DONE，必须再次本地按键才能重新执行。展示目标为约360°，实际角度误差及车心漂移需要地面测量，不能用软件累计值代替实物验收。

## 6. 网页选目标与自主寻物

### 视觉与测距

- 网页按当前COCO类别选择目标，不设置颜色条件。模型支持检测的类别与经实物验证可用于自动接近的类别分别标识；模型能识别并不代表雷达能测到。第一轮先验收一个适合展示的实物，再扩展类别。
- 场景只有一个目标实例，采用轻量单目标观测状态，不引入多目标身份选择或重识别模型。保留类别、框位置/尺度和方位的时序连续性，以排除偶发假框和跳框；若意外出现多个无法区分的候选，先停下重新观察。
- 候选出现后先停稳观察，连续至少3次不同源帧的新推理满足选定类别、置信度阈值和几何连续性才确认。类别阈值根据本机NPU实际正/负样本确定，不把置信度数值当成正确率。重复旧图像不能累积确认次数。
- 多帧确认主要抑制偶发误检，无法排除持续的类别混淆。必须测试目标不存在、相似物品、图片/屏幕中的物品、局部遮挡、远近尺度与不同光照；雷达有回波只证明存在表面，不能独立证明物体类别。必要时通过小幅安全换视角重新确认，仍有歧义则保持等待。
- 相机内参、畸变、相机/雷达外参和实际扫描高度必须标定。由框中心得到方位，将雷达点投影/关联到目标，检查连续性和遮挡，不能把框方向上最近墙面当目标距离。
- 雷达扫描平面可能高于瓶体、遇到透明材料或穿过桌腿；没有可靠目标测距时，只能报告“已发现、距离未确认”，停车或重新观察，不能按框大小宣告到达。地面接触点的单目测距只在地面假设经验证后启用。
- 初始到达目标建议车头净空约0.5m，最终按测距误差和实车制动确定；不得为靠近目标绕过现有停车线。人类目标采用更大间距并到达停车，不默认持续追踪人员。

### 演示物品与摆放条件

- CAD中的雷达光学窗口高度约186～198mm，仅作选择物品的参考，不是实测扫描平面。以实车扫描高度为准：物体在该高度有足够宽的实体截面，且从搜索到到达的距离内都能形成稳定点簇。
- 首选候选为直立的大号不透明瓶（bottle），例如高约25～30cm、主体足够宽且稳定落地的实物；这些尺寸是筛选建议，仍需实际验证类别识别和点簇。更宽的直立背包（backpack）或行李箱（suitcase）可作为备选，同样先做NPU与雷达联合测试。
- 小杯子、矮瓶、细杆、透明玻璃容器、镜面物体及只有细腿穿过扫描面的椅子不作为首轮展示目标；其视觉类别虽可能可检，测距可能不稳定。
- 优先直接放在可通行的同一地面，目标完整位于相机视野内，后方墙面及旁边杂物与其有可分辨的空间间隔。不要简单把矮目标垫高后把台座/桌腿回波当成目标；使用支架时必须明确支架几何和可接近区域。
- 开始搜索位置、绕障后的观察位置及最终停车位置都要验证相机可见性与雷达关联。初始测试可从约1m处静止观察开始，再逐步扩大范围；近距离若相机俯仰导致目标出画，须提前调整展示布局或停车距离。
- 静止观察验收通过后才允许接近：类别连续稳定、目标方位与雷达点簇匹配、距离没有关联到背景、到达区域可通行。任何一项不足都标记为未确认，不能把“看到框”直接当作运动许可。

### 任务流程

`网页选择YOLO类别 → 本地选择模式3并按S1 → 检查服务/配置 → 安全范围内分步转向观察 → 停稳并连续确认类别与测距 → 对准 → 低速分段接近并避障 → 距离/方位稳定满足到达条件 → 停车DONE`。

原地搜索一圈未找到时，在限定时间/里程内选择安全观察点、绕障移动、再次观察；记录短期已访问位置，限制重访。首版默认建议任务上限120秒、累计行驶3m，作为待验收参数。安全空间不足或预算耗尽显示NOT_FOUND/BLOCKED并停车，不无限游走。

目标暂时丢失、类别不稳定或测距关联失败时先停止接近，再有限重新观察；跳变的候选须重新确认。到达后保持停车，不因目标移动自动追赶。网页运行中更换目标类别会先取消旧目标并停车，递增任务配置版本，在当前本地授权会话仍有效时重新搜索；停止/故障/超时撤销会话后，网页更改不能重新启动。

### 分工与新增协议

- FPGA：本地模式/ARM、基础运动原语、低层速度闭环、局部雷达安全和最终电机许可。
- 4A：类别检测、误检抑制、单目标连续确认、视觉雷达关联、任务调度和观察点选择；通过新增任务协议提交有界运动请求/目标观测，FPGA再次校验并执行。
- 新建独立任务端口，暂定UDP6106和独立版本标记；ED10仍只用于显示。共用MAC接收入口需重新验证分流、FIFO流控、带宽隔离及异常包影响，不借用显示包直接控制轮子。
- 消息包括FPGA签发的本地会话标识、启动代次、目标配置版本、目标类别、请求序号、源EV10帧号、观测年龄、单目标确认代次、方位/距离有效标志、置信度、请求动作和期限。允许STOP、有限转角/行程/速度请求，禁止网络ARM、故障清除和任意PWM。
- 4A发布帧时保留真实EV10帧号；当前Assembler本地seq不是源帧号，须附加关联元数据。图像时间与姿态/雷达时间需对齐，扫描及运动中的延迟不能忽略。
- FPGA按自身帧号/接收时钟检查结果新鲜度，不依赖两端未经同步的绝对时钟。任务保活初始建议10Hz、约500ms超时，视觉观测采用独立约600ms年龄限制并经实测调整；重复发送旧观测不能刷新视觉有效期。
- NPU重启、任务进程重启、视频冻结、网络断开、命令乱序/重复/过期均应撤销相关动作；失联停车且需本地重新启动。旧会话包在停止、复位和新会话后必须失效。
- 新鲜度和会话标识不是网络鉴权；首版范围为隔离的FPGA—4A有线链路，固定源地址/校验和不能宣称防伪造。网页配置需校验输入和访问来源，配置请求本身不能使未ARM车辆运动。
- 原“所有RX数据均不可到电机”的证明不再适用于新增任务通道。替换为可验证性质：ED10仍不可控制电机；只有本地模式3/有效会话/新鲜且合法请求/全部联锁满足时，任务通道才可影响运动；模式1/2受网络数据影响必须为零。

## 7. 实施顺序与验收门槛

每阶段执行相应RTL/协议/回放/几何与同源原语检查，最终对每个新位流完成同次PNR/STA/SDF/PAD、CPU监督、CDC/RX/TX/TFT时序及视频回归，保留明确SHA和Flash审计。视频/NPU/回传需重复实测与当前吞吐、丢包、延迟及HUD显示对比。

运动验收由用户本地操作，依次架空启停、空旷地低速、障碍场景、视觉任务；电脑不ARM。用户后续已明确授权开发、编译与Flash，无需重复请求授权。每个新SHA的显示、冷启动、运动独立记录。

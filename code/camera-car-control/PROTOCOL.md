# 视频与控制协议

## 控制

主链路是电脑 RJ45 到 FPGA 的 UDP：电脑发送到 `192.168.0.2:5000`，本机绑定 `0.0.0.0:5001`；视频发送到电脑 `192.168.0.3:6102`。上位机的 UDP 端口字段填写 FPGA 控制端口。以下 EMC1 外层只用于 UDP；UART/TCP 后备直接使用旧的 AA55 帧。

### EMC1 UDP 外层

每个 UDP datagram 是：`EMC1`（4字节）+ session（uint32 little-endian）+ datagram number（uint32 little-endian）+ 一个完整旧运动帧 + CRC16-CCITT（uint16 little-endian）。FPGA 接受新 session 的 STOP 作为重新同步入口；同一 session 只接受严格递增的 number。任何 CRC、长度、版本、同步字错误都丢弃，不进入运动核心。回复保留相同 session/number，PC 只接受与当前请求匹配的 datagram。视频和控制共用以太网发送仲裁，控制回复优先。

直接复用 `../fpga/acg720-motion-control/host/protocol.py`，版本1，`AA 55` 同步，CRC16-CCITT。命令 TTL 默认250ms；主机运动循环持续发送速度并读取匹配 sequence 的状态。UART 为115200、8N1；TCP 使用**原始二进制串口透传**，无 Telnet、无 RFC2217、无换行。TCP 模块串口侧须使用同样波特率及3.3V TTL电平。COM名、IP与端口由实际设备决定。

连接仅执行 STOP、输出归零、能力探测和查询，不自动 ARM。新固件声明 `EVM1` 的 bridge_fixed 能力时自动关闭旧右轮补偿并使用现有同步减速控制；无能力回复的旧版保留用户补偿选项。清故障需要人工操作，保持停止。STOP、断开、关闭窗口会取消排队/正在执行的动作，并尝试确认 PWM 归零。电缆断开时 STOP 不能保证送达，FPGA 手动命令 TTL 为后备。

网络往返延迟及模块聚包延迟须显著小于250ms，建议关闭透传模块的长时间聚包。当前沿用原上位机的120ms请求等待上限；若链路超时立即取消动作，不会自动重连/恢复运动。

## EMV1 视频 UDP 载荷

本工程新增协议，**不兼容原厂 UDP Camera 的两字节行号协议**。FPGA 和 PC 必须使用此处定义的同一格式。默认目的端口6102，发送端 IP 192.168.0.2，电脑网卡示例192.168.0.3。监听0.0.0.0仅选择本机所有网卡，接收器仍严格过滤发送端IP。

固定20字节头；除像素数据外，整数均为**小端**。

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 4 | ASCII `EMV1` |
| 4 | 4 | frame_id，32位递增，允许回绕 |
| 8 | 2 | width，1~1920 |
| 10 | 2 | height，1~1080 |
| 12 | 2 | row，0起算 |
| 14 | 2 | 本包在该行的起始像素 x |
| 16 | 2 | 本包像素数 count |
| 18 | 2 | flags：0=数据，1=COMMIT，2=ABORT |
| 20 | count×2 | RGB565，**高字节在前**，如纯红`F8 00` |

数据包不跨行，count为1~640。RTL默认每包320像素，UDP载荷660字节。控制标记 COMMIT/ABORT 的row、x、count必须全部为0。COMMIT仅能在原始帧行宽、行数、总像素正确且未溢出后发送；否则 ABORT。COMMIT可以先于数据到达电脑，重排后收到所有像素才显示。链路层FCS/IP/UDP完整性验证由平台与电脑网络栈承担，载荷不再增加CRC。

电脑最多保留2个未完成帧，500ms过期丢弃；同一frame_id分辨率冲突或重叠像素冲突则整帧废弃，允许完全一致的重复包。只发布完整且COMMIT的帧，晚于已发布帧的旧包忽略。连续2秒无完整帧后允许重新建立frame_id序列，以处理发送端复位。界面超过1秒无新完整帧显示“画面已过期”。视频断流当前只影响预览，运动仍由距离/角度任务、STOP及TTL管理。

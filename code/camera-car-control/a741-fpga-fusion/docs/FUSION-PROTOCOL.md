# A741 FPGA 融合协议 v1

所有新增整数小端，位置单位 mm；16-bit 有符号航向一周为 65536，正值左转。地图坐标 x 前、y 左，原点为地图中心，栅格 `(x+3200)//50`，范围 0～127。

## 控制命令

既有 EMC1 UDP 5000/5001 会话、请求序号、内外 CRC、TTL 及 STOP 建立会话规则不变。能力查询 0x40 的 0x0800 位代表本接口。0x55 等运动命令不能盲目重发。地图修改、位姿与目标设置应先 DISARM；0x55 只在所有安全门满足时接受。

| 命令 | 载荷 | 语义 |
| --- | --- | --- |
| 0x50 | u8 mode | 0 清图待上传，1 人工探索建图；撤销旧地图提交，归零预览位姿 |
| 0x51 | u8 op, u16 offset, u8 count, data | op=0 读，op=1 写；offset 为压缩字节偏移，count=1～24；写入长度必须等于 4+count |
| 0x52 | u32 CRC32 | 冻结/提交整图；探索建图允许输入 0，由 FPGA 返回生成 CRC；上传必须匹配真实 CRC |
| 0x53 | i32 x, i32 y, i16 yaw | 设置初始位姿，范围 ±3100 mm，需要有效校准 IMU |
| 0x54 | u8 gx, u8 gy, i16 yaw | 设置目标，范围 0～127；停车时可预览膨胀与规划 |
| 0x55 | 空 | 请求导航，几何未核实返回拒绝；规划期间零轮速 |
| 0x56 | 空 | 取消导航并 DISARM，与 STOP 相同停车优先级 |
| 0x57 | 空 | 查询导航状态 |
| 0x58 | u8 op，追加时后接 u8 gx,u8 gy,i16 yaw | 软核路径点任务：清空0、追加1、启动2、取消3、进度4；详见 TASK3-4.md |

回复内帧类型 0xD0，固定 32 字节。byte0：0 成功，1 安全门拒绝，2 运动/地图繁忙，3 坐标越界，4 整图 CRC 不匹配。0x51 读数据从 byte4 开始；0x52 在 byte4～7 返回实际 CRC。

0x57 布局：

| 偏移 | 类型 | 字段 |
| --- | --- | --- |
| 0 | u8 | 返回码 |
| 1 / 2 | u8/u8 | 导航状态/故障原因 |
| 3 | flags | bit0 正在导航，1 完整雷达有效，2 位姿有效，3 已定位，4 地图已提交，5 探索建图，6 正在规划/准备，7 几何已核实 |
| 4 / 8 | i32/i32 | x/y mm |
| 12 / 14 | i16/u16 | 航向/车体前方净空，65535 表示无距离结果；新版本已扣除整车前外廓，不是雷达原始距离 |
| 16 / 20 | u32/u8 | 地图版本/匹配支持率百分比 |
| 21 | u8 | 保留 |
| 22 / 24 | u16/u16 | 剩余路径索引/已展开节点，节点计数显示饱和于 16383 |
| 26 | u32 | 编译的几何/雷达配置 CRC32，用 `fusion_config.py` 同一规范计算 |
| 30 | u16 | 保留 |

状态 0 空闲、1 跟踪、2 低速定位扫描、3 锁定、4 规划准备或扫描后稳定。故障 1 启动门未满足、2 链路失联、3 必要输入无效、4 障碍/路径无效、5 无旋转净空、6 扫描条件失效或超时、7 十二段仍未定位、8 无路径。状态查询不能单凭“支持率高”判定定位成功，须同时检查 localized 有效位。

融合保护触发时既有电机故障 bit10（0x0400）锁存；原 bit0 租约过期、bit2（0x0004）编码器无反馈、bit4 IMU 失效仍保留。清错须人工操作，清错不会自动启动。

2026-10-24 路径点任务版本在明确启动任务后由板内 CPU 提供控制租期，CPU 心跳过期仍锁存停车；任务启动、取消与查询不允许盲目重试。任务期间外部地图/目标修改返回繁忙，不允许争抢控制。单目标、返程和多路径点 GUI 均提交软核任务；旧 `0x55` 直接控制接口仍保留原外部租期。普通有效近障碍先停车并有限重规划，传感器/CPU/电机故障不按普通障碍自动恢复。

## EMM1 独立地图 UDP

电脑与 FPGA 均使用 6104，单次一问一答；来源 IP 必须是既有对端地址。包为 `EMM1 | u32 request | u8 command | u8 length | payload | u16 CRC16-CCITT`，CRC 初值 0xffff，覆盖 CRC 前全部字节。请求仅允许 0x50～0x52，payload ≤28 字节。回复 command=0xD0、length=32，总长44；回显 request。坏 CRC、非法长度、错误端口/命令直接丢弃，绝不执行电机命令。

整图为 4096 字节，按 y 行、x 列排列，每字节从低位起包含4格，00 未知、01 空闲、10 占据、11 保留。整图 CRC32 使用 reflected 0xEDB88320，多项式初值/最终异或均 0xffffffff，与 Python zlib.crc32 一致。没有压缩、分片乱序组装、后台自动续传或运动中地图导出。每片 offset 显式寻址，全部发送完成且整图 CRC 匹配才可导航。

地图文件 JSON 格式 `A741-grid-v1`，含尺寸、分辨率、原点、base64 数据、CRC32、SHA-256、几何/标定、状态与主机时间。PGM/YAML 导出使用世界坐标朝向；GUI PNG 使用车前朝上视图。

## EMF1 遥测

UDP6103 与 EMS1/EML1 共存，约20Hz，48字节。0～3 `EMF1`，4～5版本1，6～7长度48，8～11序号，12～15 FPGA ms。16版本1，17导航状态，18原因，19几何有效，20/24 x/y，28航向，30前方距离，32地图版本，36匹配质量；后续字节保留。

EMF1 与0x57布局不同，不能直接用 NavigationStatus 解码。停止原因和有效性须结合 EMS1 / 0x57。视频仍是 EMV1，OSD 在 FPGA 生成。地图包优先级低于控制/遥测，不阻塞运动环；正在发送的以太网帧不被中途抢占。

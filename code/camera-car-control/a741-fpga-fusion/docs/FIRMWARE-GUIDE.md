# A741 MPU6050 固件使用与注意事项

2026-10-20更新：本页下方主要保留默认P4禁用诊断和IMU硬锁测试的步骤。当前新增独立运动+LD06实验变体，CTL H20/DATA H14、机械轮距234mm、ToF未接入。应先阅读[当前交付索引](../release/README.md)及[LD06建图指南](MOTION-LIDAR-MAPPING.md)，不能把下方旧默认变体的“无传感器端口”“机械轮距为空”等说法用于新变体。最新位流未烧录、时序未签核，不能作为运动验收版。

本说明适用于 A741 的 MPU6050 分支。A740 已运行过的结果不能作为 A741 验收记录；旧 JY901 诊断位流也不能用于 MPU6050。

新增陀螺仪接口启用、电机硬件锁定的独立测试变体；具体操作优先参阅 [MPU6050测试步骤](IMU-TEST.md)。本页下方“P4禁用”描述针对默认旧诊断变体，不适用于名称含IMU-TEST-MOTOR-LOCKED的新包。

## 先确认交付状态

当前构建入口生成 `A741-MPU6050-diagnostic-P4-disabled` 诊断变体：传感器物理端口未启用，上位机禁止对该变体使能电机。它用于源码、工具流程和离线回归核对，不是完成传感器接线和运动验收的上车版本。

以下三个结论必须分开判断：

| 结论 | 检查证据 | 能说明什么 |
| --- | --- | --- |
| 位流已生成 | 同一次构建 `result.json` 的 `compile_passed=true`、`sources_changed=false`，且 `.fs` 的 SHA256 匹配 | 工具流程完成，产物对应记录的源码 |
| 时序已签核 | `timing_signed_off` 和完整 setup/hold/recovery/removal、I/O、CDC 审查 | 目标时钟和接口条件下的时序要求已核实 |
| 实板已验收 | 对应位流/配置的静止、架空、落地、故障和并发原始记录 | 接线、方向、精度与故障行为经过实测 |

**只生成 `.fs` 不能证明时序通过。** `compile_passed=true` 也不能证明 FPGA 可按要求可靠运行。检查本次交付目录的 `result.json`、`a741.tr` 和验收表；具体违例数与余量以该目录为准，不将旧报告数字套用到新位流。若 `timing_signed_off=false` 或仍有未解决的时序问题，不用于电机运动或精度验收。

同样，`hardware_programmed=false` 表示构建程序没有执行烧录；仿真通过不等于板上已经成功运行。当前电气条件和实测项目见 [硬件核对表](HARDWARE.md)、[MPU6050 替换记录](MPU6050.md) 和 [实板验收表](../verification/ACCEPTANCE.md)。

## 接线核实

2026-10-20更新：用户明确指出旧模块原理图错误，该图撤销。有效商品规格标注VCC输入 **DC 3～5 V**，用户采用3.3 V；照片为单排8针。ACG720 CSV确认六个球号标LVCMOS33，物理针序和Bank实际电压仍待核实，详见 [MPU6050.md](MPU6050.md)。

旧图的VCC_5V网络、J1/J2针序、4.7 kΩ上拉及AD0下拉结论全部撤销。当前图片无法确定上拉电阻、电源轨或AD0默认电平；无需据旧图将供电改成5 V。

当前记录保留用户实际球号，不交换 SCL/SDA：

| MPU6050 信号 | FPGA 球号 | 设计用途 |
| --- | --- | --- |
| SCL | L18 | 主 I2C 时钟，启用后采用开漏 |
| SDA | M20 | 主 I2C 数据，启用后采用开漏 |
| XDA | A1 | 辅助 I2C 数据，保持高阻 |
| XCL | B2 | 辅助 I2C 时钟，保持高阻 |
| AD0，用户写作 ADO | M17 | FPGA保持高阻；模块地址选择默认电平未知 |
| INT | B1 | 输入预留，驱动当前轮询状态寄存器 |

**球号不是排针针号。** SCL/SDA上拉电平、AD0状态、板卡连接器针号/方向及Bank VCCIO仍待实测/核实。确认公共地和信号兼容后才可启用I/O，不能把5 V信号接入FPGA。CSV原网络名不改变用户确认的SCL=L18、SDA=M20新用途。

接线、改线和插拔扩展模块时先断电，逐项核对 3.3 V 与 GND。外部模块使用独立电源时要按实际电路处理共地与供电，不能将两个电源输出未经核实直接并联；不要带电试接不确定的针脚。

提供的 `doc/模块资料/mpu6050/测试程序` 包含 51/Arduino 源码，可核对寄存器、地址和量程，未提供模块电路或板卡电气证据。原厂章节的约束文件可核对球号占用，不能替代连接器针序和 Bank 电压检查。

XDA/XCL 是辅助接口，不作为主 SCL/SDA 使用；当前不启用辅助 I2C 主机。AD0 应在电气核实后具有确定的高或低电平：低地址为 7 位 `0x68`，高为 `0x69`。驱动自动探测两地址不能补救悬空的 AD0，也不构成驱动 M17 的授权或电气依据。

VL53L1X 和 LD06 的分配仍是待核实预留，见 [HARDWARE.md](HARDWARE.md)。当前构建没有传感器物理端口，不会因插上传感器就获得数据。不要自行添加 `A741_P4_VERIFIED`、更改约束或把 `hardware_verified` 改成 `true` 来绕过核实；启用版本还需要有效约束、重新构建、时序审查和静止验收。

## 下载与上电顺序

本次构建脚本只生成文件，不烧录 FPGA。电脑和 FPGA 的 RJ45 连接用于视频、遥测和运动控制；当前工程未实现通过该连接下载位流。

工程目标记录为 `GW5AT-60B`、器件 `GW5AT-LV60PG484AC1/I0`。真正下载前，应与板上实际器件、板卡版本及 Gowin Programmer 中识别到的器件核对，不能仅凭工程名确认兼容。

当前 P4 禁用诊断包不用于上车。后续有经过时序与电气核实的候选包时，按以下顺序进行首次验证：

1. 保存当前已验证 A740 固件及其哈希，保留可恢复版本。不要覆盖 A740 归档。
2. 断开电机驱动功率电源 VM，避免下载、复位和检查过程中车轮受驱动；逻辑供电和各模块供电按实际硬件资料连接。
3. 使用板卡适配的下载器与 Gowin Programmer，核对目标器件、待下载 `.fs`、变体和 SHA256。先选择易恢复的 SRAM 调试流程；Flash 固化在候选版本验证完成后再进行。
4. 下载后保持电机 VM 断开，观察复位、LED、网口、DDR、摄像头与显示状态，再核对遥测有效性。下载工具显示成功只表示传输完成。
5. 完成传感器静止验收后，才进入架空电机测试；架空通过后再进行低速落地测试。

若位流仍有严重时序违例，不能通过“先下载试试”来替代修复。若出现方向异常、停止失效、数据跳变或通信反复断开，应撤销驱动并保留日志，查明原因后人工恢复。

| 项目 | 当前设置 |
| --- | --- |
| 物理连接 | 电脑 RJ45 直连 FPGA，链路要求 1 Gbps |
| 电脑网卡 IPv4 | `192.168.0.3`，掩码 `255.255.255.0` |
| FPGA IPv4 | `192.168.0.2` |

确认选的是接 FPGA 的网卡，避免其他网卡使用同一网段产生路由歧义。若 Windows 防火墙阻止流量，为这台电脑使用的 Python/上位机和上述端口添加适当的本地规则；不需要关闭整个防火墙。

界面不会在启动时自动连接或使能电机。连接过程先发 STOP 建立会话，再检查 A741 能力和 MPU6050 模型 ID `6050`，下发并回读配置。能力 bit4 表示 A741 接口，bit5 表示传感器物理端口已启用；当前诊断变体不设置 bit5，拒绝 ARM 是预期行为。

摄像头主视图为网络 `400×240` 抽样画面，HDMI 为 `800×480`；两端分辨率不同并不表示传感器不同步。网络拥塞允许丢视频帧，视频不能反压运动控制和 HDMI。该独立性已进行相应仿真，实板并发能力仍待测。

## 标定与日常操作

统一参数在 [config/calibration.json](../config/calibration.json)。界面“标定参数”在停止并断开连接后编辑、保存；修改参数后递增 `revision`，重新连接核对配置。不要在运行期间改文件并假设 FPGA 已自动采用新值。

| 参数 | 调整依据 |
| --- | --- |
| `wheel_cpr` | 左右编码器每圈实际计数，历史初值为 1469/1471 |
| `wheel_diameter_um` | 左右有效滚动轮径，单位微米，历史初值 66300 |
| `mechanical_track_um` | 实测机械轮距，单位微米，当前为空；运动前必须完成 |
| `historical_encoder_turn_track_um` | 234000 只保存历史转向补偿，不参与弧线几何 |
| `speed_step_mm_s_per_10ms` | 每 10 ms 目标速度变化量；5 对应 500 mm/s² |
| `pwm_step_per_10ms` / `pwm_limit` | PWM 变化量/上限；初始 8/512，512 对应沿用的 50% 上限 |
| `imu_yaw_sign` | 平放 Z 轴安装下的转向符号，按实物左右转动核实 |
| `tof_offset_mm` | ToF 到车身前缘等参考面的安装偏移，单位 mm |
| `hardware_verified` | 电气条件已核实的记录；不是用来消除报错的开关 |

历史上的距离不足、转角偏差和起停不顺畅不能都归因于 PID。轮径/CPR、轮胎打滑、机械轮距、速度限幅、零速分支更新周期、电机起动门槛和制动惯性都会影响结果。先核实测量尺度和方向，再用同地面、同载荷日志调节加减速/PWM；目前 PI 初值尚未完成实车整定。

硬件、时序和静止验收完成后的操作顺序为：

1. 保持小车静止、模块近似水平，连接后查看 IMU、ToF 和 LD06 的有效状态。
2. 点击“静止校准”。控制器使用 64 个静止角速度样本估计 Z 轴零偏，检查加速度近似水平及重力范围；车辆移动时不进行校准。
3. 架空检查前进/后退、左右轮方向、限幅、停止、取消与断连保护。每次动作由人主动启动。
4. 落地从 `100 mm/s` 开始，分别测试 20 cm、100 cm 直行、左右 90° 旋转和弧线，至少各三次，外部尺量/角度测量与日志一起保存。
5. 目标为 100 cm 外部误差不超过 ±2 cm、90° 外部误差不超过 ±5°。未达标时保留失败结果继续标定，不能用内部读数接近目标代替外部测量。

连续驾驶必须按住按钮；释放、失去焦点或界面停止续约将结束驾驶。距离和旋转任务可用“停止 / 取消”中止，完成后不自动重新启动。控制器有命令超时保护，但 UDP 停止报文仍可能丢失，实际停车时间和距离须通过故障试验测量。

正常起停和换向在 100 Hz 控制周期内执行斜坡；STOP、失联和故障立即撤销桥输出。撤销电驱动不代表车身瞬时停住，惯性滑行与驱动器自身刹车行为仍取决于实际机械/电气条件。

## 传感器与安全规则

MPU6050 当前是平放安装、绕 Z 轴的**相对航向**方案，不是带磁力计的绝对罗盘，也不是完整三轴姿态融合。每次静止校准建立相对参考；震动、温度和陀螺仪零偏会造成长期漂移，加速度不能消除绕重力轴的航向漂移。倾斜安装和任意轴安装尚不支持。

MPU6050 主 I2C 为 100 kHz，驱动配置 100 Hz 采样、±2 g、±2000°/s 和 42 Hz 低通，初始化后核对身份及配置。不要拿 Arduino 示例的 ±250°/s 默认换算直接解释本固件数据。采样间隔异常超过 30 ms 会使航向失效，数据超过 150 ms 失效；IMU 故障停车并作废校准，恢复后须人工清故障、重新静止校准和启动。旋转中不静默改用编码器转角。

未校准时，上位机显示“未校准”。当前 HDMI 的 YAW 数字可能仍显示内部初始化的 0；必须结合上位机校准标志和传感器有效性判断，不能把该 0 当作已校准的航向。

ToF 以扣除安装偏移后的前向净空为依据：≤250 mm 停车，250～500 mm 线性降速，超过 150 ms 无效。这些是待实测初值，只约束前进及前向弧线。后退没有前方 ToF 的保护承诺；LD06 当前只采集和显示，不作为自动避障依据。触发停车或故障后必须由人确认现场、清故障并重新启动，不自动续跑。

LD06 坏包、CRC 错误、角度断点、丢包或断流会使当前扫描失效；失效画面不能作为仍有实时障碍物感知的证据。运行时同时查看状态和采样时间，而不只看最后一张扫描图。

## LED 与排查

以下为 A741 的逻辑定义，表示对应 `led[n]=1` 时的状态。实物亮灭取决于板卡 LED 极性，编号和极性仍需实板核对；不能套用 A740 的定义：

| LED | 含义 | 排查方向 |
| --- | --- | --- |
| D0 | 网络 PLL 锁定 | 板时钟、复位、PLL |
| D1 | 摄像头初始化就绪 | OV5640 供电、既有接线、初始化 |
| D2 | PHY 初始化就绪 | PHY 复位/初始化；仍需电脑确认 1 Gbps 链路 |
| D3 | DDR 校准完成 | DDR 时钟/复位/初始化和原厂依赖 |
| D4 | 完整显示帧可用 | 摄像头到 DDR 完整帧路径 |
| D5 | DDR/显示错误 | DDR 和像素读取状态、相关日志 |
| D6 | 视频 FIFO 溢出 | 网络视频负载、链路、FIFO/域跨越 |
| D7 | 运动故障 | 遥测故障位和停止原因，处理原因后人工恢复 |

D0/D1/D2 亮不能单独证明系统正常；D7 灭也不表示允许 ARM。先读状态、能力、配置、校准和数据有效标志。

| 现象 | 优先检查 |
| --- | --- |
| UDP 连接失败/中断 | FPGA IP/电脑网段、1 Gbps 链路、防火墙、5001 端口占用、往返超时和丢弃计数 |
| 连接成功但拒绝运动 | 是否为 P4 禁用诊断变体、硬件核实/机械轮距配置、IMU 校准/有效性、故障位 |
| 无视频 | D1/D3/D4、6102 端口占用、收图帧号/负载、DDR 诊断；控制连接成功不代表视频正常 |
| IMU 一直无效 | 当前诊断包本身无物理端口；启用候选包还应查上拉/AD0/地址/身份/配置回读 |
| 前进立即停车 | ToF 失效/过期/过近、安装偏移、其他锁存故障 |
| 旋转后不再启动 | IMU 失效、校准失效、稳定后角度超差或命令超时；查看原因，禁止盲目重发动作 |
| 雷达画面清空 | 数据过期、坏包、丢包或角度不连续，按失效处理 |

只修改约束时可以使用 `build.py pnr` 复用已经完成的综合。脚本先核对全部 RTL 哈希、综合网表和综合选项；不匹配就拒绝复用，必须执行 `build.py build`。它仍要求本次生成的新位流和报告，不将旧产物作为成功结果。最终 `result.json` 中 `synthesis_reused` 表明是否复用了综合，综合网表哈希一同记录。

本轮时钟约束先根据原厂 IPC 定义静态 PLL 父时钟，再定义显示 `/5` 和 DDR 用户时钟 `/4`，保留 33 MHz/100 MHz 目标。静态 0°/50% 模型不等于已经验证 DDR 动态校准、所有时钟延迟和外部 I/O；除建立/保持、复位恢复/移除外，还必须阅读最小脉宽报告。

归档脚本要求构建和测试对应当前源码，并校验位流哈希；归档成功仍不会把 `timing_signed_off` 或硬件验收改成通过。缺少本次有效结果时，不能使用目录里残留的 `.fs` 作为新构建。

# 11:13 网络超时复现与诊断扩展

现场原始记录位于 `.local/control-debug/20261022-111322/events.jsonl`。101 次只读诊断请求成功 88 次、失败 13 次（12.87%）；初始 STOP 成功，失败全部为 0x44。每次失败前后 good 模16计数相同，桥状态 RECEIVE、拒绝计数0，下一条均成功；所有记录包含遥测。成功耗时0至约16ms（含计时分辨率影响），失败约250至266ms。用户 GUI 另外报告0x30参数写入连续超时，不能用只读测试代替配置连接成功。

分析时有线网卡 Up/1Gbps，192.168.0.2 路由走以太网192.168.0.3。坏FCS已饱和15，不能把13次超时全部归因于FCS。现有证据支持排查控制桥之前的收帧路径，但并未确定PHY/板级时序根因。

本次新增EMN1独立32位计数包，记录MAC有效入FIFO、坏FCS、坏帧、RX FIFO溢出事件；使用MAC已同步到逻辑域的输出，不增加直接多位CDC。每50ms发送一次，主机同时记录请求前后接收诊断和包时间。保持原厂PHY初始化、EMC1/EMS1/EML1、运动保护和命令超时不变，不增加运动重试，不声称已修复丢包。测试应关闭GUI、保持VM断开，刷入本次独立诊断构建后运行diagnose-control.cmd。时序未签核之前不得以此进行运动验收。

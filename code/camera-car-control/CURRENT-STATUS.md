# 当前运行状态与标定

本记录汇总2026-10-19的A723运动控制对话和A740融合控制对话。结论按源码、构建报告、用户日志和目测反馈分别记录。

## 已完成与证据边界

- A723在FPGA轮速PI后修正右桥极性，上位机自动关闭旧右轮反相；保留轮速闭环、失联与无反馈停车。
- A723第一次20cm测试为悬空，轮周残差约3.4/3.7mm；第二次落地出现左右交替停启、右侧无反馈。后续取消8mm进度差直接停单轮和停稳后低速补进，改为限幅、平滑地减慢领先侧。
- A740接入OV5640、PHY/MAC/ARP/IPv4/UDP，通过同一RJ45承载EMV1视频与EMC1控制。摄像头沿用P7 TY-OV5640模块，不使用DDR3或HDMI。
- 用户报告成功运行。提供的日志有多次“动作完成”“PWM归零”，也有较多超时、误差超限和 `faults=4`。日志可支持运动链路已运行，不能据此证明所有方向精度合格或视频帧率、长时间收图稳定性。
- 日志中的轮周误差来自编码器换算，不能代替尺量车体距离或实际转角。`faults=4`表示有运动目标时缺少编码器反馈，不足以单独判断是线缆、静摩擦、负载、电源还是控制输出原因。

## 使用与版本

电脑静态地址 `192.168.0.3/24`，FPGA `192.168.0.2`；UDP控制PC5001到FPGA5000，视频6102。当前MAC仅支持1Gbps。运行 `launch.cmd` 或 `.venv/Scripts/python.exe host/app.py`，选择UDP。摄像头设置和LED见 [板级说明](rtl/README.md)。

A740归档位流User Code为 `0000A740`，当前SHA256为 `98b41b4cbddf258d2759e12f10f8afd7f86c63e73e4160e6f3c778826d79eda5`；此前首版为 `50fc704bc19df9fcef4e10be55260079576525a1e9da580bcf059f4cb9cc5cf9`。两个构建共用了User Code，所以身份应以文件哈希区分。用户未提供下载后哈希回读，不把运行反馈绑定为新版位流的独立验收。

`release/A740-20261019/audit.json` 中 `hardware_tested=false` 是自动打包时的记录；后续人工反馈记录在本文。5项RTL全量日志来自首版测试，后续PI修改只单独重跑PI用例，不能声称当前位流已重新通过全部5项。Python测试和模型也不等于实车精度验证。

只用正常结束且无通信/故障中断的动作标定。记录指令角度、实际角度、方向、轮速和完成状态，以重复测量结果判断，不凭单次目测保证90度精度。直行不足尚无“指令距离/尺量距离”配对数据，因此未据此虚构距离补偿系数。

## 尚待解决

1. **起停不顺畅**：上一轮“PI输出按斜坡归零”的描述不准确。当前零目标分支每个50MHz时钟递减一次，而非每个10ms控制周期；512幅值、50步长约11个时钟就归零，未形成可感知的平滑停车。主机的0.2秒停车尝试已撤回，当前没有该阶段。修复需设计正常减速、单轮到达、换向与立即STOP的边界，再测试和构建；本文不声称已修好。
2. **通信超时**：网口也会显示共享协议层的“串口没有匹配回复”。实际原因尚未定位，需结合UDP收发、视频负载和硬件时序排查，不能只归因于串口或PID。
3. **精度与无反馈**：直行距离不足、转弯偏差和 `faults=4` 仍需分别排查，不屏蔽故障、不自动低速补进。没有IMU或外部定位，编码器闭环无法独立证明车体真实角度。
4. **时序**：当前归档报告为setup 3、hold 27个违例端点；初版为3/26。RGMII延迟、跨时钟和复位路径尚未完成签核，I/O预算不是实板测量值。

完整软件测试入口见 [验证记录](VALIDATION.md)，构建见 [BUILD记录](BUILD-2026-10-19.md)。先处理通信和正常起停，再根据配对实测统一几何标定；本次README整理不修改运动逻辑或执行硬件动作。

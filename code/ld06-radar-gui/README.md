# LD06 激光雷达 GUI

独立的中文 Python 桌面程序，采用简洁白色界面，通过 USB 转串口 / PWLINK2 接收 LD06，显示 360° 极坐标点云、连续回波轮廓和周围距离。根据“调试激光雷达”的对话（2026-10-20）实现：使用 **230400 baud、8N1、无流控**，直接接收雷达主动输出的数据，不需要 PowerWriter 串口助手。

## 启动

需要 Python 3.10 或更高版本，带 Tkinter（Windows 官方 Python 通常包含）。在本文件夹执行：

```powershell
python -m pip install -r requirements.txt
python app.py
```

Windows 可直接双击 `launch.cmd`。如果本文件夹存在 `.venv`，启动器优先使用其中的 Python。

没有实物时，双击 `demo.cmd`，或运行：

```powershell
python app.py --demo
```

模拟数据会明确标为“模拟数据”，展示房间边界和圆形障碍物，不代表实测。

## 连接你的雷达

1. 保持已经验证能旋转、能收到数据的接线，连接 PWLINK2。
2. 关闭 PowerWriter / SSCOM 的串口连接，释放 COM 端口。
3. 打开本程序，点击“刷新”，选择 PWLINK2 对应的 COM；也可手动输入。
4. 点击“连接雷达”，观察有效帧、接收字节和点云。

也可指定端口启动，例如 `python app.py --port COM7`。COM7 只是示例，需要替换为实际设备端口。

数据线为 **雷达 TX → 适配器 RX，并共地**。程序只接收 UART 数据，不向雷达发送命令，不控制 CTL/PWM、电源或电机。CTL 接法继续以你手里设备的资料及已验证接线为准。

FPGA集成属于另一套[A741网口工程](../camera-car-control/a741/README.md)，当前实验分配为CTL H20、DATA H14；早期对话里的G1/H2是历史候选，已经被替换，不能照旧接。切换到FPGA外部PWM控制前应断电核对接线，CTL不能同时直接接地和接FPGA输出，H14的USB_PA3复用冲突仍待核实。此串口GUI没有FPGA通信、地图积分或导航功能。

## 界面操作

- 雷达中心为原点，**原始 0° 朝上，90° 朝右，角度顺时针增加**；它们不自动代表车头或地理方向。
- 默认开启“障碍轮廓”：相邻且距离连续的回波连成蓝线；缺测或深度突变处断开。浅蓝色仅表示连续测距扇区，不等同于已确认可通行区域。取消勾选可看原始散点。
- 前/后/左/右显示对应方向 ±30° 扇区内有相邻回波支持的最近距离；孤立单点不用于方向距离，缺测显示“无回波”。“前方”指显示上方，安装后需要用“旋转”对齐实物方向。
- 橙点标记当前最近回波，距离在 1 m 内用厘米显示；它仍可能是单个孤立回波。鼠标移到回波附近可查看该点的实际距离、原始角度和信号强度。
- “旋转”可按安装方向旋转画面；CSV 保留雷达原始角度，同时记录旋转量和显示坐标。
- 显示半径默认“自动”：按有效回波距离的第 95 百分位留 20% 余量选择量程，少量远点可能被裁掉；图头显示实际半径。可手动选择 0.2–12 m，或用鼠标滚轮缩放。绘图量程不代表设备在所有环境下都能达到该距离。
- 默认过滤信号强度低于 10 的点，零距离始终不显示；支持设置为 0 排查弱回波。
- 默认“保留”最近 0.6 秒点云，新扫描覆盖同一区域，过期点自动清除；这是滚动点云，并非 SLAM 地图。
- 频率由设备包内角速度 / 360 换算；“当前最近点”只统计通过筛选且在显示量程内的点。
- “暂停画面”冻结点云，后台仍接收；“继续显示”回到最新画面。“清空”保留累计接收统计。
- “导出 CSV”保存当前画面通过筛选的点，包含来源（demo/serial）、原始角度、距离 mm、信号强度、显示旋转角和 x/y 米坐标（右为 +x，上为 +y）。

## 接收诊断

### 桌面小物体移动不明显 / 方向对不齐

先固定半径为 `0.5 m`、保留时间为 `0.2 s`，最低强度 `10`。自动量程会把较远的背景一起纳入，几厘米的移动可能显得很小。

当你认定的实物正前方显示在图的左侧，且当前旋转为 `0°` 时，将“旋转”改为 `90°`，即可把原左侧转到上方。这是当前摆放方向的校准，不是所有 LD06 通用的零点定义。当前程序重启后需重新选择该设置。

小摆件可能只有顶部经过扫描高度。用竖直、不透明的纸板，在雷达正前方约 20–40 cm 处测试，让纸板高过雷达侧面的扫描窗口，再左右移动。用这个对照确认回波和方向，再换回小摆件。不要只看全局最近点：它可能一直是别的固定物体；应观察纸板所在方向的回波。

| 现象 | 排查 |
| --- | --- |
| 没有 COM | 检查 USB、驱动，点击刷新；端口列表为空时也可手动输入 |
| 无法打开 / 拒绝访问 | 确认端口号，关闭其他占用该串口的软件 |
| 字节数不增加 | 检查供电、共地、雷达 TX 到适配器 RX、USB 连接 |
| 字节增加但无有效帧，CRC 错误增加 | 检查设备型号、适配器是否支持 230400、串口信号与接线 |
| 有效帧增加但无显示点 | 调低最低信号强度，扩大量程，确认距离非零 |
| USB 拔掉后显示中断 | 插回设备，刷新并重新连接；不自动重连 |

## 协议与实现

每帧 47 字节，固定 `54 2C` 开头，所有多字节字段小端：

| 字节偏移 | 内容 |
| --- | --- |
| 0–1 | 帧头 `54 2C` |
| 2–3 | 角速度，°/s |
| 4–5 | 起始角，0.01° |
| 6–41 | 12 个点，每点距离 uint16（mm）+ 信号强度 uint8 |
| 42–43 | 终止角，0.01° |
| 44–45 | 设备时间戳，ms |
| 46 | 前 46 字节 CRC8，多项式 `0x4D`、初值 0 |

按首尾角度对 12 个点插值（除以 11），支持跨 360°。解析器支持任意分块、噪声、粘包和 CRC 失败后逐字节重新找帧。串口读取运行在后台线程，通过有界队列交给 Tk 主线程；点云最多 720 个角度格。界面约每 33 ms 刷新，过载丢块会显示计数。

串口按每次最多 1024 字节、40 ms 超时批量读取，避免旧版逐字节入队导致的队列溢出。界面每次最多用 12 ms 处理接收队列，避免积压时阻塞窗口；若出现丢块，先丢弃未完成帧再重新同步。

厂商实现核对来源（2026-10-20 读取）：

- LDROBOT 官方 SDK：<https://github.com/ldrobotSensorTeam/ldlidar_stl_sdk>
- 帧、角度与 CRC：<https://github.com/ldrobotSensorTeam/ldlidar_stl_sdk/blob/master/ldlidar_driver/src/dataprocess/lipkg.cpp>
- 波特率配置：<https://github.com/ldrobotSensorTeam/ldlidar_stl_ros2/blob/master/launch/ld06.launch.py>

本程序为独立 Python 实现，未复制厂商驱动源码，也未接入 ROS、FPGA 或小车控制。

## 验证

```powershell
python -m unittest discover -s tests -v
```

包含拆帧、随机分块、噪声/错帧恢复、CRC 参考值、跨零度插值、小端字段、无效角度、点云过期/零回波覆盖、模拟数据、串口打开失败与干净退出测试，以及实际 Tk GUI 的暂停、筛选、过期和 CSV 导出测试。GUI 测试需要图形桌面会话。

开发早期系统未枚举COM，仅验证模拟；后续已查看用户接入的COM9实物窗口，接收计数持续增加，队列丢块为0。设置显示旋转90°、半径0.5 m、保留0.2 s后，用户用20～40 cm竖直纸板移动作对照，确认“会变化，方向也正确”。此结果只覆盖该次连接、方向和纸板高度，不代表小摆件检测、测距精度或FPGA/PWM/建图已验收。端口号可能变化，显示参数重启需重选。完整过程见 [验证记录](VALIDATION.md)。

主要文件：`app.py`（GUI）、`protocol.py`（解析）、`receiver.py`（串口线程）、`scan.py`（点云与坐标）、`view.py`（轮廓、方向距离和缩放）、`demo.py`（模拟帧）。

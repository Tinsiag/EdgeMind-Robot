# 运动控制实施与验收计划

更新日期：2026-10-13。本文件区分设计目标、已有初版和待完成工作；当前源码行为、参数和已知问题以 [工程 README](README.md) 及 [上位机说明](host/README.md) 为准。

## 目标与当前基础

目标：独立 GW5AT-60B FPGA 位流，全 RTL 编码器反馈和双轮 PI；通过板载 CH340E Type-C/UART 的 Python CLI 实现前进、后退、左右转向、单次指定角度原地旋转及停止。不依赖摄像头、DDR、软核、IMU 或 ToF。

已有：50 MHz / 20 kHz PWM / 100 Hz 控制的工程初版、UART CRC 帧、编码器计数、测速、PI、差速和旋转模块，以及六个基础 testbench。最后 P&R Fmax 50.013 MHz、setup/hold 0 违例；尚无实车证据，测试不足以证明完整闭环和安全状态链。

## 1. 先完成联调修复

- 修复状态 TX 的 start/busy 握手及 Python 分包解析；使用引脚级 UART 测试完整 35 字节状态帧和 CRC，覆盖连续请求、坏帧、半帧及同步恢复。
- CRC 成功后原子提交命令；验证版本、各命令长度、参数范围、序号和半帧超时。参数仅在 DISARMED 修改；ARM 要求完整且有效的配置。
- 验证上电默认禁止、S0 异步禁止与同步释放；STOP、失联、故障必须取消旋转及待提交目标，清积分和旧输出，重新 ARM 后不自动恢复。
- 反馈无脉冲检测按“当前轮目标要求运动”启动，提供启动宽限；清故障时清相关错误来源；静止、零目标及单轮测试不应误报。任一需要运动的轮反馈异常应停止双轮。
- 修复 PI signed 运算、16 位截取和范围限制，补条件积分抗饱和、斜坡、目标为零处理和零速换向保护。实现独立方向映射与可标定 PI 增益，7/8 保留 ID 未实现前不宣称可调。
- 恢复精确差速换算：`offset = omega_mrad_s × wheel_base_mm / 2000`；当前 `/2048` 近似和低 16 位截取需替换或明确限定范围。直接轮速命令也必须限幅。
- ROTATE 只提交一次，锁存角度/速度/起始计数，单独续期；到位后结束并等待新命令。STOP/超时可取消，添加执行超时和 no-progress 判据；避免读取后来串口帧的 payload。
- CLI 保持同一连接和解析器，50 ms 定时续期并读取状态；加入目标/实测轮速 CSV、Ctrl+C/finally STOP 和断线重连后重新解锁。

每项修复后执行相应回归；完成源码改动后重新检查实际引脚、3.3 V IO 和 20 ns P&R 时序，不能沿用旧报告。

## 2. 实物标定

先架空车轮、使用受限供电，复核 FPGA 型号、CH340E COM 口、编码器 A/B 3.3 V 电平及现板接线。停止输出后手转每侧多圈，记录输出轴 CPR、正反计数、左右前进符号与非法跳变；再测有效轮径和两驱动轮中心距。

```text
speed_mm_s = delta_count × pi × diameter_mm × 1000 / (CPR × sample_ms)
counts_per_mdeg_q16 = round(wheel_base_mm × CPR × 65536 / (360000 × diameter_mm))
rotation_counts = angle_mdeg × counts_per_mdeg_q16 / 65536
```

1456 CPR、轮径和轮距只能按实测记录配置。旋转公式先用于对称轮组理论初值，左右轮参数差异和地面打滑须另行校正。电流、VM 电压及电池电压由外部仪表测量，当前遥测没有电压通道。

## 3. 闭环与动作验收

1. UART HELLO/STATUS 完整帧；未配置、未 ARM、复位和下载不输出 PWM。
2. 单轮开环观测和参数标定，确认驱动方向与反馈极性一致。
3. 单轮比例响应、积分整定、不同目标阶跃、反向、停止和负载变化；记录目标、实测速度、输出、采样时间及外测电压。
4. 双轮架空前进/后退，再落地低速；弧线左右转向及 `v=0` 原地转动。
5. 单次 +90°/-90° 到位停车，重复运行，测外部实际车体角度；报告误差和条件，不以计数到位替代车体角度测量。
6. S0、拔串口、错误 CRC、错长度、过期/重复帧、编码器断线/非法跳变、故障恢复测试；恢复通信或清故障不得自动继续动作。

项目原需求的 ≤5% 稳态轮速误差和 ±90° 旋转争取 ≤5° 是待确认验收目标；需要固定速度、载荷、地面、电量和测试方法。记录逻辑禁止延迟、车体停止时间及停车距离，不能把 PWM 低电平当作机械瞬停。

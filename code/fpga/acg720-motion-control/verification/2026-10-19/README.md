- 左/右90°都有faults=4提前结束的样本，也有“编码器目标已达到，已发送STOP”的样本。故障样本中一侧目标仍未达到、计数停滞约200ms；需要排查低速起动力矩、转向机械阻力、输出/反馈，而不是把该次不足90°直接归结为轮距标定误差。

## 结合当前代码的判断

1. **右轮内部PI符号仍需修正。** A722桥命令直接使用pi_r，而GUI默认将右目标反号、编码器保持车身前进为正。以实际前进为例，内部右目标为负、测得反馈为正，误差相加，PI可能长期到512限幅；日志也多次出现右PWM512、左PWM随反馈下降。应在FPGA的PI后反转右桥命令，保持目标/反馈同号，再关闭GUI补偿。仅把GUI补偿取消而不修固件会改变实物方向。
2. **末段缺少同步控制。** GUI给每轮独立使用剩余距离×4计算速度，最低目标40mm/s；单轮到达后立即设零并锁存到达，另一轮继续追赶。双轮行程差不会通过共同轨迹纠正；00是滑行，先到侧没有主动保持或制动。日志与这一行为相符，属于明确的控制改进点。
3. **万向轮是待检因素。** 两个前万向轮的滚动/回转阻力、偏置、接地负载与地面条件可能影响差速动作。当前没有拆分实验，不能判定其为主要或唯一根因。先检查是否卡滞、擦碰、车架扭曲/某轮悬空、驱动轮是否易打滑；转向对比时固定初始万向轮方向、地面和载荷。
4. **目前不宜直接标定补偿90°。** 先让动作稳定完成且无故障，处理滑行/低速停滞，并确认右轮轮速负反馈。对反复无反馈的低速段先找最低可持续速度、摩擦和反馈情况，再设计受限前馈/低速控制；不是简单取消所有故障或无限增大输出。

## 后续实现和标定顺序（计划，尚未实施）

1. 修正FPGA右桥极性，关闭GUI反向补偿，分别验正/反转目标和计数同号，确认两轮能以相近实测速度跟踪。
2. 直线按左右归一化行程误差调节两轮目标，领先侧适度减速；用共同剩余距离和速度规划减速。转弯同步两侧相反的轮周进度，避免一轮先到后另一轮单独追赶。
3. 停车考虑实际速度与可测减速度，提前减速并记录撤输出后的滑行；结束条件加入两侧速度收敛及停稳后行程。若需主动制动，先核对AT8236实际模式、供电和电流，不凭猜测改成两输入同高。主机遥测间隔约40ms加串口往返，有到达判定延迟，精度需求高时把轨迹环放FPGA。
4. 修正双轮速度环后，在固定地面/电量/载荷下校准有效左右轮径与轮距。前后直线各多次，左右90°各多次，同时记录停稳计数与外部角度。先校轮径和直线一致性，再校转角。
5. 仅对无故障、无明显滑移且重复性好的转角样本使用：`有效轮距新值 = 旧值 × 目标角度 / 实测角度`。例如期望90°、多次实测平均80°，理论初始修正为121.4×90/80≈136.6mm；这是有效运动学参数，不是把实物轮距改为136.6mm。该例不是本车已测值，也不建议当前直接套用。若左右转偏差不同或散布很大，先处理不对称/摩擦/打滑，不能用一个比例掩盖。
6. 若编码器行程一致但实际车体仍偏航或打滑导致转角不稳定，再增加IMU偏航反馈；实现航向外环和轮速内环，并处理静态偏置与漂移。没有IMU时只能做轮式里程计估计，不能观测所有轮胎滑移。

现阶段最优先的是右桥极性与双轮同步控制。前万向轮无需因本日志立即换成固定轮；固定前轮会改变原地差速转向条件，是否改机械需另做验证。此次没有采购或改机械的建议。

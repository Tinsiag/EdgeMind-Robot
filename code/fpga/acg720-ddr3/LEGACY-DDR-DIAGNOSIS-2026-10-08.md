# 旧摄像头 DDR 诊断的确定缺陷与未确认根因

2026-10-08 复核。旧 F15/B21 FIFO 诊断的“仅 D0 亮”对应 DDR PLL 锁定、DDR 校准未完成。它没有进入后面的摄像头像素比较阶段，因此不能把该灯态称为已经发生像素不一致，更不能直接判断 DDR 芯片损坏。

## 可从代码和 IP 配置确定的缺陷

| 项目 | 旧代码证据 | 后果 | 新基线处理 |
| --- | --- | --- | --- |
| PLL mDRP 被屏蔽 | `camera_ddr_fifo_bist.v` 的 `pll_init_bypass(1'b0)`，原主工程也存在 | 外部 mDRP 无法接管 DDR PLL，相关逻辑被综合优化 | 原厂 16 拍锁定延迟后交出控制权，适配器综合网表保留 |
| 写数据量不足 | 只回放 index 0～15，共 16×16 bit；`wr_bust_len=8` | 写 FIFO 只有 2 个 128-bit 块；适配器要求 `wfifo_rcount >= 8` 才启动 WRITE，输入耗尽后不会启动该写批次 | 800×480 完整帧；按通过的官方 200-block 调度，检查 48000 个实际接受的写命令 |
| 未等待有效写入就读 | 无实际写完成握手，固定延时后进入读状态；适配器本身可先读 | 可能读到尚未由本次测试写入的 DDR 内容 | 全帧实际写命令完成及输入帧检查通过后才允许读 |
| FWFT 比较错位 | IP `.ipc` 为 `FWFT=true`、`OUTPUT_REG=false`；旧比较用 `rd_fire_d`，但未锁存 pop 当拍 Q | pop 后下一拍的 Q 已指向后一个像素，连续读会将不同序号数据相比较 | pop 当拍采样 Q；静态逐像素和摄像头 CRC 仿真覆盖空读暂停 |
| 一次性捕获事件可能丢失 | 捕获不等待校准，cap_toggle 仅在 ST_WAIT_CAP 检查 | 如果事件在 ST_WAIT_CAL 阶段到达，切换状态后可能永久等不到新的事件 | 摄像头在 DDR 校准后才启动；完整帧完成状态持久保存并同步 |

源文件在 `.local/camera-ddr/src/camera_ddr_fifo_bist.v`；官方适配器在 `.local/ch47/src/ddr3_ctrl_2port/fifo_ddr3_adapter.v`，写 FIFO Rnum 是 128-bit 读侧块数量。旧地址上限 24 也与 8 个块的批次不匹配；新整帧使用 384000 个 16-bit 地址单位。

表中后四项发生在校准之后，**不能解释旧板上 D1 灭**。捕获事件是否实际提前到达未测得，只能确定代码存在这种失败路径。

## 尚未证实的唯一原因

新第 38 章基线修正 mDRP、使用不同系统 PLL/参考时钟拓扑并重建测试调度，已完成实板校准及 768000 字节静态整帧读回。这是可用链路的直接证据，但同时变化多处，尚没有仅修正 mDRP 的旧诊断 A/B 灯态，不能称为唯一根因已经锁定。

旧诊断的校准失败仍可能涉及 PLL 控制、时钟拓扑、复位或布局变化。当前不再依赖存在上述逻辑缺陷的短窗口旧诊断判断 DDR 硬件。通过基线与新增摄像头整帧版分别保留，旧文件未改写。

本轮第 38 章旧生成 FIFO 的 RP0007 / SSRAM 综合兼容性问题另有独立综合证据，替换为配置逐字节相同的官方第 47 章实现后编译通过；它解释本轮综合失败，不是旧已下载诊断的校准失败证据。

静态通过记录见 [FRAMEBUFFER-TEST-RESULT-2026-10-08.md](FRAMEBUFFER-TEST-RESULT-2026-10-08.md)。摄像头彩条 `0x4FCF`、实景 `0xAF89` 的独立整帧 CRC 均通过对应实板反馈确认，未复用静态灯态作为摄像头成功证据。详见 [排查与实现文档](DDR3-FRAMEBUFFER-IMPLEMENTATION-2026-10-08.md)。
